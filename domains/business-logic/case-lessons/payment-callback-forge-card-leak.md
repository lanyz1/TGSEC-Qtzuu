# 案例课：发卡站支付回调伪造 → 未授权读卡密

> 脱敏。适用于 dujiaoka / 易支付(yipay) / 同类签名回调发卡站。

## 攻击链（授权验证用）

```text
1. POST 创建订单 → 得 order_sn
2. 进入支付网关页 → 泄露 pid / sign 参数结构
3. 若 merchant_pem 可从网关/配置/复用通道反推
4. 按文档算法 ksort + md5(串+key) 构造 notify
5. POST 支付回调 notify_url → success → 订单变已支付
6. GET 订单详情/卡密页 无鉴权或仅知 order_sn → 卡密/虚拟货泄露
```

## 根因组合

| 缺陷 | 后果 |
|------|------|
| 回调签名密钥弱/复用/泄露 | 可伪造支付成功 |
| 回调不校验 money == actual_price | 任意金额「付清」 |
| `/detail-order-sn/{sn}` 类未授权 | 知单号即可取货 |
| 订单号可创建所得 | 无需枚举 |

## 检查清单

- [ ] notify 验签密钥是否独立随机、非前端/URL 复用
- [ ] 回调是否校验金额、商户号、订单状态机（防重放）
- [ ] 卡密/详情是否强制邮箱+查询密码或登录态
- [ ] export-carmis 是否仅支付后+归属校验
- [ ] 未支付订单限流是否可被 XFF 绕过

## 修复

独立 merchant key；金额强校验；详情鉴权；幂等与 order 状态；轮换已泄露密钥。

## 与 ROI

总代/强后台 bcrypt 打不动时，**平行资产发卡站** 可能是「可变现」高 ROI 链——授权范围内优先支付逻辑面。
