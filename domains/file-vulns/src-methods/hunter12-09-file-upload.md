# 第九技 · 文件上传 —— 一张图片的三十六种身份

> 猎手视角：上传漏洞的乐趣在于"身份错位"——Web 服务器以为它是图片，解析器以为它是脚本，杀软以为它是文档，而它，什么都是。

**目标读者**：具备基础 Web 测试经验的安全工程师
**前置要求**：HTTP 协议、常见 Web 服务器与解析规则概念

---

## 何时启用本技

- 头像、附件、导入（Excel/CSV）、素材库等一切上传口
- 上传后的**访问路径可预测**（图片能直接打开）——这是 WebShell 落地的前提
- 文件被服务端**二次处理**（预览、转码、解压）——这是解析漏洞与 zip 攻击的前提

---

## 一、原理拆解

上传安全的本质是一道多选题，每一问都可能出错：

```
1. 前端校验了吗？        → （可绕过，不算防线）
2. 后端校验什么？        → 扩展名黑名单/白名单/MIME/幻数
3. 存到哪？             → Web 目录？随机名？保留原名？
4. 能被解析吗？          → 服务器把 .php/.jsp 当代码执行的条件
5. 会被二次处理吗？       → 图片压缩/解压/转码引入新战场
```

危险组合 = 校验漏洞（1、2）+ 可解析存储（3、4），或 = 二次处理漏洞（5）单独成立。

---

## 二、五步猎洞法

### 第一步：识面 —— 摸清上传的"生命周期"

上传前（前端限制？）、上传中（校验了什么？看报错规律）、上传后（URL 长啥样、扩展名是否被改、能否直接访问）。每上传一个探针文件就记录一条链路。

### 第二步：定点 —— 校验类型探测

用一系列"探针文件"摸清校验策略：

| 探针 | 结果 → 判断 |
|------|-------------|
| `shell.php` | 被拒 → 有扩展名校验 |
| `shell.php.jpg` | 成功且被改名 `.jpg` → 服务端强制改名（好防御） |
| 改 MIME 为 `image/jpeg` 传 `.php` | 成功 → **只校验了 MIME**（大洞） |
| 图片头 + `<?php ... ?>`（GIF89a 拼接） | 成功 → 只查幻数或没查 |
| `shell.phtml / .php5 / .pht` | 成功 → 黑名单漏网（变体绕过） |
| `.htaccess` 上传 | 成功 → Apache 场景可让 `.jpg` 当 php 解析 |

### 第三步：验证 —— 落地路径与解析

上传成功只是上半场，**解析成功才算进球**：

- 访问上传文件 URL，看内容被**原样下载**（安全）还是**执行**（RCE）
- 探针内容用无危害验证：`<?php echo "pwn-test-ok"; ?>`，回显即证实
- Nginx/Apache 解析特性测试：`shell.jpg/x.php`（Nginx php-cgi 老版本）、`shell.php%00.jpg`（老 PHP 截断）

### 第四步：利用 —— 按场景选攻击链

**经典 WebShell 路线**（扩展名校验绕过后）：找可解析后缀 → 传免杀小马 → 连接。生产环境仅证明 `phpinfo()` 级别证据。

**存储型攻击链**（不追求服务端执行，攻击"看文件的人/程序"）：

| 载体 | 攻击 | 目标 |
|------|------|------|
| SVG 头像 | 内嵌 `<script>` 存储型 XSS | 浏览该头像的用户 |
| HTML 附件 | 钓鱼跳转/虚假登录页 | 下载打开的用户 |
| `.docx/.xlsx` | XXE（内部 XML 加 DTD） | 服务端解析器 |
| `.zip` | Zip Slip（`../` 路径穿越解压） | 解压服务 |
| 压缩炸弹 | 解压资源耗尽 | 解压服务（DoS，慎用） |
| CSV 导入 | `=WEBSERVICE()` 公式（CSV 注入） | 打开表格的运营人员 |

**图片二次处理**：ImageMagick 老版本（`ImageTragick`，`push graphic-context` 利用）、图片缩放库历史 RCE。

### 第五步：收官 —— 定级与证据

- 解析成功 RCE：最高危，`phpinfo` 截图即停
- 仅绕过校验但不能解析：降级为"上传校验缺陷"，配合其他条件才有危害，报告里写明前置条件
- 存储型链（SVG→XSS）：按对应漏洞定级

---

## 三、实战推演（虚构场景）

> 场景：授权测试虚构 CMS `cms.demo-example.com`（Nginx + PHP），素材上传功能

1. **识面**：`POST /upload`，前端限制 jpg/png；上传成功后返回 `/uploads/2026/09/xxx.png`（随机名，扩展名保留）
2. **定点**：传 `a.php` 拒绝（扩展名黑名单）；`a.phtml` 拒绝；`a.php.jpg` 上传成功且保留 `.jpg`——但 MIME 改 `image/jpeg` 后传 `a.php` 成功且**扩展名保留**——只校验 MIME 实锤
3. **验证**：访问 `/uploads/2026/09/a.php`，`<?php echo "probe-".PHP_VERSION; ?>` 正常输出 PHP 版本号——解析成功
4. **利用**：证据已足，不传 webshell；顺手测 SVG 上传点：内嵌脚本的 SVG 能直接被访问（存储型 XSS 加分项）
5. **收官**：报告高危（上传校验绕过 → RCE），修复：扩展名白名单 + 随机重命名 + 存储目录禁执行

## 四、对抗与绕过

| 防线 | 绕过思路 |
|------|----------|
| 扩展名黑名单 | 变体：`phtml/php5/pht/Php`（大小写）；Apache `AddHandler` 场景 `x.php.abc` |
| MIME 校验 | 报文里 `Content-Type` 想写啥写啥——与服务端实际能力无关 |
| 幻数校验 | 文件头拼马：`GIF89a` + 代码（校验不过全文 hash 才有效） |
| 白名单 `.jpg` | 解析漏洞路线：Nginx `x.jpg/x.php`（老 php-cgi）、`.htaccess`/`.user.ini` 先行 |
| 重命名防御 | `%00` 截断（老 PHP/Java）、路径穿越写文件名 `../../shell.php` |
| 存储目录隔离 | `/.well-known/` 等特殊目录、备份文件 `.bak` 可解析残留 |

---

## 五、防御视角

1. **白名单扩展名 + 随机文件名 + 独立存储域**（无脚本执行权限的 CDN/OSS）
2. 校验三层做全：扩展名（白名单）、幻数（finfo）、文件尺寸上限
3. 存储目录**禁执行**：Nginx `location ~* ^/uploads/.*\.(php|jsp)$ { deny all; }`
4. 二次处理：ImageMagick 启用 security policy、解压前校验路径（防 Zip Slip）与压缩比
5. SVG 单独域渲染或强制 `Content-Security-Policy` + `Content-Disposition: attachment`

---

## 六、踩坑记录

- 上传成功 ≠ 漏洞：**找到能访问的 URL 再说**。很多上传走 OSS 私有桶，根本没执行语境，报告写 RCE 就闹笑话了
- `.phtml` 没反应先看 Nginx 配置：`location ~ \.php$` 只匹配 `.php` 结尾——解析不解析是**服务器配置**决定的，换后缀前先测 `phpinfo` 变体
- `Content-Type` 想当然填 `image/jpeg`：先抓正常上传图片的包看真实报文，MIME 拼错一次浪费一轮测试
- SVG XSS 在"直接访问"场景有效，若站方用 `<img>` 标签引用则脚本不执行——**验证要按真实渲染方式**
- Zip Slip 测试解压目录：解压在 `/tmp` 危害为零，要写穿越目标是**应用代码目录**才定高危——先摸清解压逻辑再构造路径

## 七、速查卡

```text
校验探测: 改MIME | 双扩展 | 变体后缀 | .htaccess
解析确认: 上传 php echo 探针 → 访问看回显
Nginx老洞: shell.jpg/x.php | PHP老洞: %00截断
存储链:   SVG→XSS | docx→XXE | zip→Slip | csv→公式注入
防御:     白名单+随机名+独立域+禁执行
```
