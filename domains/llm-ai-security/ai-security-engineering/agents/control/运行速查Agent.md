# 速查卡 Agent

## 核心口诀速查

| 场景 | 口诀 | 触发 Agent |
|------|------|----------|
| 通用研判 | 先认人后认事，单点不判跨层成链 | 实体解析Agent + 基线检查Agent |
| 加密流量 | 密文不看字，看节律包型去向上下文 | 加密流量分析Agent |
| Webshell | 壳会换皮会话不会，抓交互不背指纹 | WebShell研判Agent |
| 逻辑漏洞 | 逻辑不看招式，看权看物看状态 | 逻辑漏洞研判Agent |
| 离地攻击 | 白器不白行，父子参数定真章 | 离地攻击研判Agent |
| 编码混淆 | 编码只是壳，解壳看行为 | 编码混淆分析Agent |
| 跨告警 | 同窗不同案，有因有果才成链 | 跨源关联Agent |
| 白名单 | 白名单验原因，不是见白就放行 | 白名单验证Agent |
| 事前渗透 | 不知全貌不可动手，不画地图不可行军 | 安全验证规划Agent + 环境画像Agent |
| 闭环 | 事前不测事中无基，事中不判事前无功 | 统一编排Agent |

---

## 六句真言（背下来）

> 先认实体，后认行为；先看基线，后谈异常；
> 单点不判，跨层成链；
> 特征可伪，行为难藏；
> 密文看形，逻辑看权；
> 白名单验因，命中不免；
> 证据闭环，再做定性。

---

## 十二字操作法

**认实体 → 找基线 → 核权限 → 看行为 → 串因果 → 找反证**

---

## 五道门禁（标 HIGH 前全过）

| 门禁 | 一句话 |
|------|--------|
| A 实体完整性 | 事件关联同一实体或因果链？ |
| B 行为违反 | 有违反基线的具体行为？ |
| C 独立佐证 | 至少一个独立数据源确认？ |
| D 良性解释 | 最强正常解释已评估？ |
| E 来源追溯 | 每个主张能追到源字段？ |

---

## 置信度速判

| 条件 | 置信度 |
|------|---------|
| 2+ 独立证据维度 + 违反不变量 + 因果可追溯 + 良性解释无法覆盖 | **high** |
| 基线显著偏离 或 2 源佐证 但因果不完整 | **medium** |
| 仅 1 弱异常 / 多良性解释 / 实体不确定 | **low** |

**严禁**仅因以下单一因素判 HIGH：JA3 命中、熵值高、单一指纹、三条告警、周期性、境外 IP、LOLBin。

---

## 高置信度证据门槛

单一网络指标 **不得**直接标 HIGH。高置信需跨维度独立证据；端点遥测可得时优先取端点证据：
- 进程执行 / 文件创建
- 未授权对象访问
- 凭据使用 / 横向认证
- 特权操作 / 命令执行
- 业务对象状态变更

---

## 关系符号

| 符号 | 含义 | 使用条件 |
|------|------|---------|
| `A → B` | 因果 | 同实体 + 必要条件 + 时序 |
| `A + B` | 佐证 | 独立源确认同一行为 |
| `A ~ B` | 可能相关 | 时间/空间接近但证据不足 |

---

## 输出八段（顺序不可变）

1. **【结论】** 恶意 / 高度可疑 / 待验证 / 良性 / 信息不足
2. **【核心证据】** 最多 5 条，每条带 provenance
3. **【证据链】** → / + / ~ 三种关系
4. **【正常解释】** 最强良性解释 + 能否完整覆盖
5. **【置信度】** high / medium / low
6. **【缺失数据】** 仅列可能改变判定的数据
7. **【MITRE ATT&CK】** 仅行为充分时映射
8. **【响应建议】** watch / enrich / collect / contain / isolate / block

## 复杂环境速查

| 环境 | 研判陷阱 | 正确做法 |
|------|---------|---------|
| DHCP | IP 漂移 → 归因错误 | 查租期快照 + 时间窗口 |
| NAT/代理 | 源 IP 隐藏 | 查 X-Forwarded-For + 映射表 |
| CDN | WAF 看到边缘 IP | 查回源 IP + SNI |
| K8s Pod | IP 频繁变 | 用 Pod ID + namespace |
| 容器 | 可见性取决于 runtime/CNI/sensor 部署 | Runtime/Node/eBPF/云审计多源补齐；NetworkPolicy 是控制，不是取证数据源 |
| 多租户 | 跨租户访问 | 强制 tenant 校验 + 行级隔离验证 |
| 无服务器 | 无 EDR 代理 | API 网关日志 + 云审计 |
| 共享出口 | 源 IP 是 NAT 网关 | 内部日志关联 + 会话 ID |

## 公式化速判（给 Agent 算，不给规则绑架）

> **异常度 = 偏离程度 × 基线可信度；证据强度 = 独立性 × 直接性 × 完整性；置信度 = 证据强度 − 反证强度。**

### 1. 调查优先级

```text
Investigation Priority
= Asset Criticality
× Anomaly Strength
× Exposure / Reachability
× Detection Gap Prior
× Time Sensitivity
```

- `Detection Gap Prior` 只决定“先查谁”，**不得进入恶意证据分**。
- 高价值资产 + 强异常 + 已知可达攻击面 = 优先调查；不等于已经入侵。

> 金句：**风险决定先后，证据决定真假。**

### 2. 证据强度

```text
Evidence Strength
= Σ(Evidence Weight × Independence × Reliability × Causal Fit)
− Contradiction Penalty
```

参考权重只用于排序，不是硬阈值：

```text
直接行为证据（命令执行/越权成功/恶意文件落地） >
跨源行为佐证（身份+端点+网络/API） >
强上下文异常（角色/时序/对象边界） >
统计异常（频率/包型/周期） >
单一 IOC / 指纹命中
```

> 金句：**一条硬证据，胜过十条像攻击。**

### 3. 置信度与严重度分开算

```text
Confidence = Evidence Completeness + Source Independence + Causal Consistency − Benign Explanation − Missing Critical Evidence

Severity = Business Impact × Privilege × Blast Radius × Persistence × Data Sensitivity
```

因此允许：

```text
高置信 + 低严重度 = 确认恶意，但影响有限
低置信 + 高潜在严重度 = 证据不足，但必须优先补证
```

> 金句：**置信度回答“是不是真的”，严重度回答“出了事有多疼”。**

### 4. 因果链

```text
A → B 成立
= Entity Continuity
+ Temporal Order
+ Mechanism Compatibility
+ Artifact / State Continuity
```

四项中缺关键项时，只能降为 `A ~ B`；攻击路径模板命中只能增加 `Hypothesis Fit`，不能代替现场证据。

> 金句：**时间能排顺序，机制才能定因果。**

## AI 安全工程双主线速查

```text
AI for Security：攻击面治理 Agent → 安全验证 Agent → 检测 Agent → 调查研判 Agent → 响应处置 Agent → 复盘进化 Agent
Security for AI：输入与上下文安全 Agent → 身份与权限安全 Agent → 工具与MCP安全 Agent → RAG与记忆安全 Agent → 动作策略安全 Agent → 数据防泄漏 Agent → AI供应链安全 Agent → AI红队评估 Agent
```

- **攻击路径是地图，不是现场。**
- **盲区是 Prior，不是 Evidence。**
- **Prompt Injection 是入口，权限失控才是事故。**
- **模型可以提议动作，但模型不能给自己授权。**
- **检索到，不等于可信；记住了，更不等于事实。**
- **别只测模型说了什么，要测系统最后做了什么。**
