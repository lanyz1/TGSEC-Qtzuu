# 单 IP 黑产农场三件套打法 — 143.14.49.16 案 (2026-09-29/30)

**目标**: 单 IP 上 36-40 套系统 (TG 监听/群管 + E 策略平台 + 假投注 + 号商分发), 32 端口; 取证 2048 文件/78MB
**成果**: 集群接管 (多系统 admin 全入), 证据链完整落盘

## 农场地图 (multi-app triage)
- **端口即应用**: 8088/8091/8099 = TG 监听三件套 (mgmt/admin/bot_panel); 8888 = E 策略平台 (客户端); 其他端口=群管/发卡/假投注
- 同 IP 多栈并存 (PHP/Flask/Node/Swoole) → 指纹逐端口分离, 勿混
- TG bot_panel 数据源标记: 8091_mgmt / admin_8088 / admin_8099 / bot_panel / group_admin

## 进入链 (要点)
1. **E 策略平台**: 开放注册 → 客户面板越权 → 平台代管客户 **Gate.io API 密钥** 面 (资金面直接暴露)
2. **TG 监听 admin**: 弱口令 + 未授权接口 → 全量消息/身份提取
3. **Flask 系**: SECRET_KEY 跨系统共享 → 一处泄露=多系统 session 伪造
4. **锁定规避**: per-IP 锁定 → Tor 电路轮换 (IsolateSOCKSAuth 凭据级隔离)
5. **身份矩阵**: TG 监听面 → 操作者全身份 + 资金流水 (ledger/identity 数据集, 存档不入库)
6. **假投注证据**: 投注数据系伪造 (系统界面展示假记录)
7. **号商分发链**: 账号→渠道→下游 完整链路取证

## 教训
- 单 IP 农场先做"端口→应用"矩阵, 再横向比对共享凭据 (SECRET_KEY/DB/session)
- 运营核心资产 = TG 监听面 (消息流=身份+资金) → 优先打
- Tor IsolateSOCKSAuth: 同端口多凭据=多出口电路, 破 per-IP 锁定
- 收尾必须: 全量取证 + evidence_index (2048 文件规模参考)
