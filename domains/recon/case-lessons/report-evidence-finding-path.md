# 案例课：报告结构 — Evidence → Finding → Path

> 从多份实战报告抽象的交付写法。

## 推荐骨架

1. **目标画像**：栈、CDN、角色、API 前缀  
2. **Evidence**：可复现命令 + 关键响应（脱敏）  
3. **Findings**：编号、级别、位置、影响、修复、evidence_ids  
4. **Path**：从入口到目标的步骤链  
5. **未突破面表**：试了什么、为什么停（防「假打穿」）  
6. **修复优先级**  
7. **产物路径**（仅客户环境，知识库不收真实货）

## 级别与诚实

| 表述 | 何时用 |
|------|--------|
| 数据层打穿 | 跨租户/库存级泄露已 PoC |
| 可变现链 | 支付伪造等业务资金影响（授权范围内点到为止） |
| 未完全控制 | 无 admin/RCE 时明确写 |

## PoC 合格

- 他人按步骤可重做  
- 有请求/响应或截图索引  
- 不把 scanner 未验证项写成已确认
