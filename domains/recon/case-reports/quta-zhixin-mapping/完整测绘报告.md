## 一、平台架构总览

### 1.1 智信选伴是什么

智信选伴是一套 **多品牌社交/交友 App 运营平台**，采用「双实例后端 + 26+ 马甲包前端」模式运营。所有马甲包共享统一的 API 框架（Phalcon PHP），通过 CDN Host header 路由到不同后端实例。

### 1.2 双实例架构

| 属性 | 实例A（科轩系） | 实例B（聚益系） |
|------|----------------|----------------|
| API 域名 | `apppi.xivis.cn` | `api.kevvi.cn` |
| 数据库 | `yuanban_api`（独立） | `yuanban_api`（独立） |
| 框架 | Phalcon PHP | Phalcon PHP |
| CDN IP | 103.41.2.41 等 | 同一组 IP |
| 管理面板 | 134.175.163.112:30080/30085 | 未暴露 |
| 马甲包 | 趣她、幽爱、善遇、青汐恋、幽雅 | 果友、久聊、伴你、慕寻、青杉荟 |

**关键发现**：同一个 `user_number`（如 68310090）在两套实例中对应 **不同的用户**。两套实例完全独立，仅共享 CDN 入口 IP 和 OSS 存储。

### 2.1 Phalcon API 测试端点未授权（Critical）

`/v1/test/` 命名空间下的多个诊断端点 **无任何鉴权**，可直接访问：

| `/v1/test/shortpostsNewListDiag` | 帖子列表 + **完整 SQL 查询泄漏** | High |

| `/v1/test/getPhoneById?uid=xxx` | 任意用户手机号查询 | High |

#### 2.1.1 `/v1/test/ac` — 全量用户数据泄漏

- 返回 **72MB** PHP array dump，包含平台全部活跃用户
- 暴露字段：`user_id`、`user_number`（8 位展示号）、`user_nickname`、`user_avatar`、`user_gender`、`user_height`、`user_profession`、`user_birth`、`user_member_flg`、`user_real_certification_flg`
- 总量：**54,200 条帖子**，去重后 **23,637 个独立用户**

#### 2.1.2 `/v1/test/shortpostsNewListDiag` — SQL 查询泄漏

响应中 `d.sql.sql` 字段直接暴露了完整的 SQL 查询语句，泄漏了：

- **数据库名**：`yuanban_api`
- **表结构**：`user`、`user_account`、`user_stat_profile`、`short_posts`
- **字段名**：全部 SELECT 字段及 JOIN 条件
- **过滤逻辑**：`user_gender` 性别过滤、`user_written_off_flg` 注销标记、`user_login_forbid_flg` 封号标记

泄漏的完整 SQL：
```sql
SELECT c.short_posts_id, u.user_id, u.user_number, u.user_nickname, 
       u.user_avatar, u.user_height, u.user_profession, u.user_gender,
       c.short_posts_update_time, u.user_real_certification_flg, ...
FROM yuanban_api.short_posts AS c
INNER JOIN yuanban_api.user AS u ON u.user_id = c.short_posts_user_id
INNER JOIN yuanban_api.user_stat_profile AS usp ON usp.user_id = c.short_posts_user_id
INNER JOIN yuanban_api.user_account AS ua ON ua.user_id = u.user_id
WHERE c.short_posts_status = 'Y' 
  AND u.user_written_off_flg <> 'Y'
  AND ua.user_login_forbid_flg <> 'Y' ...
```

## 九、方法论

### 9.1 数据提取流程

```
1. 发现 /v1/test/ 未授权端点
   ├── /v1/test/ac → 72MB PHP dump → 解析 23,637 用户
   ├── /v1/test/pay → 5 个微信商户凭据
   ├── /v1/test/getPhoneById → 批量提取手机号 (99.8%)
   └── /v1/test/shortpostsNewListDiag → SQL 泄漏 + 帖子时间戳

2. 微信支付商户账单拉取
   ├── 用泄漏的 API Key 签名 downloadbill 请求
   ├── 遍历 3 个可用商户 × 90 天
   └── 解析 CSV 格式账单 → 5,068 笔交易

3. 数据关联
   ├── user_id → user_number 映射（ac 端点）
   ├── user_id → phone 映射（getPhoneById）
   ├── user_id → coin 映射（recharge/index）
   ├── user_id → last_active 映射（shortpostsNewListDiag 帖子时间戳）
   ├── OpenID → user_id 映射（已有 181 条，来自历史数据）
   └── 合并生成 Excel 报告
```

### 9.2 未能突破的方向

1. **SQL 注入**：WAF（自定义 HTTP 461）+ ORM 参数化双层防护，测试了 URL 编码、混合大小写、内联注释、HPP、multipart、chunked encoding、信任头绕过，全部被拦截
2. **支付宝数据**：API 仅暴露微信支付商户配置，支付宝商户凭据未在任何端点泄漏
3. **完整 OpenID 映射**：微信 OpenID 按 AppID 隔离，平台 API 不暴露 OpenID ↔ user_id 查询，订单号不编码 user_id，WeChat orderquery 的 attach 字段仅含 `recharge|wxgfkx2qxl` 类标签
