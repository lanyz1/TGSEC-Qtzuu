# 云身份低影响验证与证据清单

## 1. 范围门

- [ ] 目标属于自有系统、明确授权项目或隔离实验室。
- [ ] 已记录账号/项目/订阅、区域、集群、命名空间和允许测试身份。
- [ ] 已写明允许动作、禁止动作、数据敏感度和停止条件。
- [ ] 未获授权的真实目标只做公开资料学习，不发起探测。
- [ ] 不执行 DoS、持久化、无界爆破、生产写入、权限扩大或范围外访问。

任一项不满足时，只输出测试设计，不执行环境验证。

## 2. 攻击面清单

- [ ] 低信任输入：URL、Webhook、文件、插件、第三方代码或本地低权限用户。
- [ ] 请求能力：协议、方法、请求头、DNS、重定向、代理和出站网络。
- [ ] 本地能力：进程用户、容器权限、宿主挂载、`hostNetwork` 和节点访问。
- [ ] 身份入口：VM metadata、节点 IMDS、容器凭据接口、projected token、身份代理或 Workload API。
- [ ] 身份映射：实例/节点角色、ServiceAccount、issuer、subject、audience、trust domain。
- [ ] 凭据旁路：环境变量、配置文件、静态 Secret、SDK provider 和缓存。
- [ ] 资源 Sink：云控制面、对象存储、数据库、密钥服务、消息系统或跨账号角色。
- [ ] 证据源：配置历史、身份日志、云 API 审计、网络拒绝和应用日志。

## 3. 观察与假设

每个检查先填写：

- **观察**：已经读取到的配置、策略、代码或事件。
- **假设**：观察可能导致的身份路径或资源影响。
- **下一项检查**：能最大幅度降低不确定性的最低影响动作。
- **支持证据**：什么结果足以支持假设。
- **否定证据**：什么结果足以否定假设。
- **证据不足**：哪些缺失会阻止结论。

禁止把扫描器结论、单次错误、单次延迟、单个网络请求或缺失日志直接写成“已利用”。

## 4. 最低影响检查顺序

### 只读配置

- [ ] 查看 metadata endpoint、协议版本、hop limit 和修改权限。
- [ ] 查看实例/节点/工作负载附加身份及资源权限。
- [ ] 查看 PodSpec、ServiceAccount、automount、`hostNetwork`、特权与挂载。
- [ ] 查看 OIDC issuer、subject、audience 和信任条件。
- [ ] 查看主机防火墙、NetworkPolicy、CNI/代理实际执行状态。
- [ ] 查看 SDK provider 顺序、静态凭据回退和缓存配置。

### 静态分析

- [ ] 跟踪用户可控 URL 到实际网络调用的解析、DNS 和逐跳重定向。
- [ ] 确认调用方不能任意设置 metadata、Host、Authorization 或转发类请求头。
- [ ] 确认错误、日志、追踪和调试输出不会记录 Token 或完整凭据响应。
- [ ] 确认资源服务器仍执行 IAM/RBAC，而不是只信任工作负载身份。

### 本地 mock

- [ ] 使用只返回无害 marker 的本地 HTTP stub 验证 URL 和重定向控制。
- [ ] 使用 mock credential provider 验证 SDK 实际选择顺序。
- [ ] 使用合成声明验证 issuer/subject/audience 的策略匹配。
- [ ] 使用合成事件验证“配置—身份—API—出口”关联逻辑。

### 隔离环境

- [ ] 只使用无敏感资源、无写权限的测试身份。
- [ ] 只验证不需要身份入口的主体连接被拒绝。
- [ ] 只验证错配 issuer、subject 或 audience 被拒绝。
- [ ] 只确认最终主体类别，不输出 Token、签名材料或凭据响应。
- [ ] 所有可写动作改为草稿、临时状态或无副作用 mock。

## 5. 证据记录

每个发现至少记录：

- 目标和授权范围。
- 前置条件与已观察事实。
- 待验证假设。
- 实际执行的最小检查。
- 时间、主体、资源和配置版本。
- 实际结果及支持/否定/不足判定。
- 首个失效控制点。
- 最高可能影响，不夸大未验证后果。
- 已触发的停止条件。
- 根因修复位置和复测 oracle。

证据中不得出现真实 Token、Authorization Header、私钥、云密钥、完整 metadata 凭据响应或业务数据。

## 6. 强制停止

- [ ] 即将访问凭据路径或展示真实秘密。
- [ ] 即将访问其他租户、范围外账号或非测试资源。
- [ ] 即将产生真实写入、发送、删除、权限修改或持久化。
- [ ] 测试身份意外获得超出预期的权限。
- [ ] 结果无法归因，继续操作只会扩大范围。
- [ ] 已取得证明控制有效或缺失的最小证据。
- [ ] 用户、系统策略或审批明确拒绝继续。

命中后保存非敏感证据并停止，不通过扩大 IAM、切换身份或寻找旁路继续。

## 7. 结论门

只有同时满足以下条件，才能写“已验证控制缺失”：

- 目标和前置条件在授权范围内。
- 观察结果可重复、可归因。
- 至少一个明确控制点未按预期工作。
- 结果不是单纯扫描器推断或日志缺失。
- 证据不依赖真实秘密或生产副作用。

否则写成“风险假设”或“证据不足”。

## 8. 修复与复测

- [ ] 可达性问题在应用、网络或进程边界修复。
- [ ] 身份问题收窄 issuer、subject、audience、ServiceAccount 或 attestation。
- [ ] 授权问题收窄资源、动作、条件和跨账号信任。
- [ ] 静态凭据回退和错误 provider 优先级已移除。
- [ ] 日志只保留主体、资源、动作和关联 ID，不保留秘密。
- [ ] 原失败场景现在被拒绝。
- [ ] 干净业务场景仍能安全完成。
- [ ] 修复未把身份回退到节点、实例或共享高权限角色。
