# 云身份攻击面与测试思路

## 目标

本专题用于在自有系统、明确授权项目或隔离实验室中回答：

1. 哪个低信任输入或执行主体可能接近云身份入口？
2. 入口代表实例、节点、Pod、ServiceAccount 还是具体工作负载？
3. 该身份最终能对哪些资源执行什么动作？
4. 哪个最低影响检查足以支持或否定风险假设？
5. 何时必须停止，修复后如何用同一场景复测？

公开资料不是测试授权。没有目标授权时，只能学习方法、检查公开配置样例或设计本地 mock。

## 固定决策循环

### 1. 范围

记录目标资产、云账号/项目/集群边界、测试身份、允许动作、禁止动作、数据敏感度、维护窗口和停止条件。范围不完整时，不向真实身份入口发起探测。

### 2. 架构与身份路径

按顺序画出：

`低信任输入或代码 → 网络/本地执行能力 → 元数据或凭据入口 → 身份签发/兑换 → 云 API → 资源或数据`

同时记录旁路：

- 环境变量、挂载 Secret、静态配置和 SDK 凭据链。
- 节点 IMDS、容器凭据接口、身份代理和 Workload API。
- `hostNetwork`、特权容器、宿主挂载和同机第三方 Agent。
- 日志、错误、追踪、缓存和调试输出中的凭据副本。

### 3. 观察与假设分离

观察是已取得的配置、策略、网络结果或审计事件；假设是对风险链的解释。

- “Pod 使用 `hostNetwork`”是观察。
- “Pod 因而能够取得节点角色”仍是假设，需要独立证据。
- “出现链路本地请求”是观察。
- “临时凭据已经泄露并被使用”至少还需要身份签发/兑换和资源 API 证据。

### 4. 最低影响检查

优先级固定为：

1. 只读控制面配置与策略。
2. 静态代码、IaC、PodSpec、信任策略和 SDK 凭据链。
3. 本地 stub、保留地址和无副作用 mock。
4. 隔离环境中的无权限测试身份与负向断言。
5. 只有前四项不能回答且授权明确时，才设计更接近真实环境的验证。

检查不得输出真实 Token、完整凭据响应、Authorization Header 或私钥。

### 5. 判定

每个假设预先写三种结果：

- **支持**：观察到预定义控制缺失或隔离环境中的无害 marker 到达预期边界。
- **否定**：预期控制明确拒绝，且没有旁路身份来源。
- **证据不足**：日志缺失、版本未知、控制未实际执行或结果无法归因。

扫描器告警、单次超时、单个网络事件和“未发现日志”都不能单独构成已验证漏洞。

### 6. 停止

出现以下任一条件立即停止：

- 即将读取、复制或展示真实凭据。
- 即将访问非测试资源、其他租户或范围外账号。
- 验证可能产生生产写入、权限扩大、持久化或不可逆副作用。
- 已取得足以证明控制有效或缺失的最小证据。
- 证据无法归因，继续只会扩大影响而不会提高结论质量。

### 7. 修复与复测

根因通常分为三层：

- **可达性**：不应接近身份入口的主体能够到达它。
- **身份绑定**：issuer、subject、audience、ServiceAccount、节点或进程绑定过宽。
- **资源授权**：身份权限、资源范围或条件过宽。

复测必须使用原观察、原假设和原 oracle，并增加干净对照；不能只检查“提示词是否更强”或“告警是否消失”。

## 攻击面

### 任意 URL 与 SSRF

- 评估问题：应用能否控制协议、主机、端口、请求头、DNS 结果或逐跳重定向？
- 最小检查：静态审查 URL 解析链，并用本地 stub 验证每次跳转都重新校验。
- 证据：校验前后目标、拒绝原因和实际出站计数。
- 停止点：证明链路本地/私网目标被拒绝或发现第一处可归因的校验缺口。

### VM 内本地进程

- 评估问题：低权限用户、插件、第三方 Agent 或脚本是否与高价值实例身份共机？
- 最小检查：只读主机防火墙、进程身份和附加角色配置；不读取凭据路径。
- 证据：允许访问身份入口的用户/进程集合与实例角色权限。
- 停止点：确认边界隔离或证明低信任主体位于同一可达边界。

### Pod 到节点身份

- 评估问题：业务 Pod 是否除工作负载身份外还能接近节点 IMDS？
- 最小检查：审查 CNI、NetworkPolicy、hop limit、`hostNetwork` 和节点池配置；在隔离 Pod 中只验证连接被拒绝。
- 证据：实际生效的网络拒绝、PodSpec、节点元数据模式和准入结果。
- 停止点：确认普通 Pod 被阻断，或发现首个绕过边界，不继续取得节点凭据。

### ServiceAccount 与联邦绑定

- 评估问题：issuer、subject、audience 是否精确到预期集群、命名空间和 ServiceAccount？
- 最小检查：静态解析信任策略；用无权限测试令牌验证错配声明被拒绝。
- 证据：签发声明、信任条件、拒绝日志和最终主体。
- 停止点：精确匹配通过、任一错配被拒绝，或发现无必要的宽泛条件。

### SDK 凭据链

- 评估问题：静态环境变量、配置文件或节点身份是否覆盖预期工作负载身份？
- 最小检查：列出 provider 顺序，用 mock provider 记录选择结果。
- 证据：被选 provider、来源类别和最终主体，不记录秘密值。
- 停止点：确定实际选择路径后停止。

### 共享身份与爆炸半径

- 评估问题：多个 VM、Pod、命名空间或集群是否复用同一高权限身份？
- 最小检查：只读身份绑定和资源策略，建立“主体—工作负载—资源”映射。
- 证据：共享主体数量、权限交集、条件和隔离缺口。
- 停止点：能够界定受影响集合，不枚举或读取业务数据。

### Token 生命周期

- 评估问题：短期令牌、派生云令牌和缓存是否具有不同有效期与撤销路径？
- 最小检查：读取配置和公开声明，用测试令牌验证轮换/错配拒绝。
- 证据：每层签发方、audience、TTL、缓存和撤销责任。
- 停止点：生命周期图完整，或发现无法解释的长期回退凭据。

### 证据与观测盲区

- 评估问题：能否把配置、身份签发/兑换、云 API 调用和网络出口关联到同一主体？
- 最小检查：使用合成事件或测试主体核对字段，不制造真实异常行为。
- 证据：主体、会话、资源、动作、时间线和缺失字段。
- 停止点：结论达到“支持/否定/证据不足”之一，不用额外副作用弥补日志缺失。

## 跨云观察重点

- AWS：区分 IMDSv2 会话控制、实例角色、EKS 节点角色、IRSA/Pod Identity 和 SDK provider 优先级。
- Azure：固定 `Metadata` 请求头不等于进程身份；评估 VM 托管身份共享边界、MSP 和 AKS 联邦绑定。
- Google Cloud：固定请求头和 HTTPS endpoint 不等于进程隔离；评估附加服务账号、GKE metadata server 与 `hostNetwork` 例外。
- Kubernetes：区分 projected ServiceAccount Token、节点身份、RBAC、云 IAM 和同 Pod 容器共享边界。
- SPIFFE/SPIRE：评估 Workload API socket、attestation selector、trust domain 与 JWT audience；SVID 不自动授予资源权限。

## 记录格式

每次判断至少包含：

- 授权范围与禁止动作。
- 已观察事实。
- 待验证假设。
- 最低影响的下一项检查。
- 支持、否定和证据不足的预期证据。
- 停止条件。
- 当前结论与置信度。
- 根因修复和同场景复测。
