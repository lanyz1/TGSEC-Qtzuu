# DNS 与 DNSSEC 公开资料索引

## 采集说明

- `authorization`: `public`
- `sensitivity`: `public`
- `confidence`: `verified`
- `collected_at`: `2026-07-20`
- `content_mode`: `cited-summary-only`
- 本地只保存原创中文摘要和链接，不保存第三方全文，因此原文 `sha256` 不适用。
- RFC 原文适用 IETF Trust Legal Provisions；NIST/CISA、ICANN/IANA、MITRE 内容分别受其发布机构条款约束。本学习包不假定“公开可读”等于可任意再许可。
- 时间敏感页面必须在实际部署前重新打开核对，尤其是 IANA 算法注册表、根信任锚/轮换页和 NIST 勘误页。

## 版本替代与冲突说明

1. NIST SP 800-81r3 于 2026-03-19 取代 SP 800-81-2，发布页在 2026-07-10 标注“Potential updates (errata)”。
2. SP 800-81r3 第 3.8.1 节仍把 RFC 8624 描述为算法权威来源，但 RFC 9904 已于 2025-11 取代 RFC 8624，并将规范状态移到 IANA 注册表。本包对算法状态以 **RFC 9904 + IANA 动态注册表**为准。
3. RFC 9499 取代 RFC 8499，作为当前 DNS 术语入口。
4. RFC 9156 取代 RFC 7816，作为当前 QNAME 最小化规范。
5. RFC 9718 取代 RFC 7958，作为当前根信任锚发布规范。
6. RFC 9018 更新 RFC 7873；阅读 DNS Cookies 时应同时考虑二者，不能采用 RFC 7873 附录中的旧示例算法。
7. RFC 9975 于 2026-05 更新 RFC 7344 和 RFC 7477，增加跨权威服务器的一致性要求。

## A. 总览、术语与核心 DNSSEC

### SRC-2026-5301 — NIST SP 800-81r3

- 名称：Secure Domain Name System (DNS) Deployment Guide
- 发布：NIST，2026-03，最终版；取代 SP 800-81-2。
- URL：https://csrc.nist.gov/pubs/sp/800/81/r3/final
- 用途：企业 DNS 架构、权威/递归角色、保护性 DNS、加密 DNS、DNSSEC、日志与零信任部署总览。
- 注意：发布页已有 2026-07-10 潜在勘误提示；算法选择不要照抄其 RFC 8624 引用。

### SRC-2026-5302 — RFC 9499

- 名称：DNS Terminology，BCP 219
- 发布：IETF，2024-03；取代 RFC 8499。
- URL：https://www.rfc-editor.org/rfc/rfc9499.html
- 用途：统一 Stub、递归、权威、转发器、QNAME、DNSSEC 等术语。

### SRC-2026-5303 — RFC 4033

- 名称：DNS Security Introduction and Requirements
- 发布：IETF，2005-03。
- URL：https://www.rfc-editor.org/rfc/rfc4033.html
- 用途：DNSSEC 总体模型、信任锚、Stub/验证器关系、`Secure/Insecure/Bogus/Indeterminate` 四状态和安全边界。

### SRC-2026-5304 — RFC 4034

- 名称：Resource Records for the DNS Security Extensions
- 发布：IETF，2005-03。
- URL：https://www.rfc-editor.org/rfc/rfc4034.html
- 用途：`DNSKEY`、`RRSIG`、`NSEC`、`DS` 等记录格式和规范处理。

### SRC-2026-5305 — RFC 4035

- 名称：Protocol Modifications for the DNS Security Extensions
- 发布：IETF，2005-03。
- URL：https://www.rfc-editor.org/rfc/rfc4035.html
- 用途：签名区发布、解析器行为、认证链和协议处理。

### SRC-2026-5306 — RFC 9364

- 名称：DNS Security Extensions (DNSSEC)，BCP 237
- 发布：IETF，2023-02。
- URL：https://www.rfc-editor.org/rfc/rfc9364.html
- 用途：把 DNSSEC 核心与主要扩展汇总到一个入口，并明确 DNSSEC 来源认证属于最佳当前实践。
- 注意：该文早于 RFC 9904，算法状态应再查 IANA。

2. RFC Editor 页面若显示 `Obsoleted by`、`Updated by` 或重要 Errata，先更新本索引，再更新技术卡片。
3. 若来源撤回或链接失效，保留原 `source_id`，增加状态与替代来源，不复用 ID。
