# 修复优先级

## 1. 参数化所有数据值

把 SQL 模板固定下来，通过驱动 API 单独传递参数值。不要先把值插入字符串，再把整个字符串交给 `prepare` 或 `execute`。

参数化应覆盖：

- 查询条件。
- 插入和更新值。
- 分页数值。
- 日期、布尔、枚举和数组元素。
- 存储过程参数。
- ORM/HQL/JPQL 中的变量。

## 2. 重构动态 SQL 结构

普通值参数通常不能代表标识符和关键字。以下场景采用代码内固定映射：

```text
业务输入 "created" → 固定列 created_at
业务输入 "name"    → 固定列 display_name
业务输入 "asc"     → 固定关键字 ASC
业务输入 "desc"    → 固定关键字 DESC
```

映射表之外的值直接拒绝。不要把用户传入的表名或列名经过通用转义后继续拼接。

## 3. 正确处理可变列表

对于 `IN` 条件：

- 根据元素数量生成相同数量的占位符。
- 每个元素单独绑定。
- 对元素做类型与数量限制。
- 明确定义空列表语义，避免生成无效 SQL 或回退到无条件查询。

优先使用框架或驱动提供的列表绑定能力，避免自行实现复杂转义。

## 4. 安全构造可选筛选

可选条件可以逐段拼接固定 SQL 片段，但每个数据值仍应绑定：

```text
固定片段: "status = ?"
固定片段: "created_at >= ?"
固定片段: "owner_id = ?"
```

拼接的是开发者控制的模板，不是用户输入。成熟查询构建器可以减少占位符和参数顺序错误，但 raw 接口仍需审计。

## 5. 审计存储过程

安全存储过程应：

- 使用类型明确的过程参数。
- 在静态 SQL 中直接引用参数。
- 动态 SQL 使用数据库支持的绑定变量。
- 避免把参数拼入 `EXEC`、`EXECUTE IMMEDIATE` 等命令文本。

把所有应用账号提升到数据库 owner 以便执行存储过程，会显著扩大成功注入后的影响。

# 纵深防御

## 最小权限

- 每个应用使用独立数据库账号。
- 读服务不给写权限。
- 不给应用账号 DBA、建表、扩展、文件或操作系统能力。
- 按功能拆分账号或视图，限制可见表与列。
- 数据库进程自身不使用 root/System 等高权限系统账号。

最小权限不能修复注入，但能降低成功注入的影响。

## 输入验证

用于业务正确性和结构枚举：

- 数值范围、日期范围、长度和枚举。
- 动态排序字段和方向的固定映射。
- 批量列表的元素类型和最大数量。

不要使用关键字黑名单作为主要防线。合法姓名、地址或文本可能包含特殊字符，而攻击表达也可能有多种编码和等价形式。

## 错误处理

- 对外返回稳定、无数据库细节的错误。
- 对内记录关联 ID、执行阶段和必要上下文。
- 日志中不记录口令、完整令牌、敏感 SQL 参数或个人数据。
- 隐藏错误只能减少信息泄露，不能替代参数化。

## 监控

- 关注数据库语法错误、类型错误和异常查询形状的趋势。
- 检测同一入口出现大量相近条件、异常时序或高失败率。
- 将应用请求 ID 与数据库审计关联。
- 告警用于发现残余风险，不作为代码修复的替代品。

# 特殊语义

## `LIKE` 通配符

参数化会阻止 SQL 结构注入，但 `%`、`_` 仍可能改变搜索匹配范围。这通常是业务语义问题：

- 若允许通配搜索，明确记录。
- 若只允许字面搜索，使用数据库方言支持的转义规则并指定 `ESCAPE`。
- 不要把“通配符扩大结果”误报成 SQL 注入。

## `NULL` 与类型

- 使用驱动要求的空值表示。
- 尽量显式绑定参数类型和合理长度。
- 避免因隐式类型转换造成索引失效、逻辑偏差或性能回归。

## 客户端模拟预备

部分驱动会在客户端模拟参数处理。应：

- 阅读驱动当前官方文档。
- 使用受支持的参数 API，不自行拼接。
- 对字符集、反斜杠和多语句配置做集成测试。
- 不根据“服务端未出现 PREPARE”就简单判定不安全；关键仍是代码与数据是否可靠分离。

# 回归测试清单

## 正常功能

- 普通文本、数字、日期和布尔值。
- 包含引号、反斜杠、Unicode 和空白的合法数据。
- 空值、空字符串、最大允许长度和边界数值。
- 合法分页、排序和多条件筛选。

## 安全性质

- 类 SQL 文本被当作普通数据，而不是改变结果集结构。
- 两组相反测试条件不再控制响应差异。
- 数据库错误不向外暴露。
- 动态标识符只接受固定映射。
- `IN` 列表每项独立绑定，空列表行为明确。
- 二阶路径中的持久化数据在后续查询仍通过参数传递。

## 权限与影响

- 应用账号不能访问非业务表。
- 读账号不能修改数据。
- 应用账号不具备数据库管理、文件、扩展或系统权限。
- 多个应用不共用 owner/admin 账号。

## 测试证据

每个回归用例记录：

- 修复前现象。
- 代码修复位置。
- 修复后现象。
- 正常业务对照。
- 数据库和驱动版本。
- 是否覆盖二阶及后台任务路径。

# 不完整修复

- 只隐藏数据库错误。
- 只在入口删除引号或 SQL 关键字。
- 只部署 WAF。
- 只调用 `prepare()`，但变量已插入查询字符串。
- 只修复一个接口，遗漏相同数据库封装的其他调用点。
- 只修复当前请求，遗漏报表、队列和定时任务中的二阶路径。
- 使用高权限存储过程替代字符串 SQL，却在过程内部继续拼接。
