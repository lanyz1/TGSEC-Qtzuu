# 分类原则

SQL 注入可以按“应用暴露什么观察信号”“输入位于查询何处”“输入何时进入危险查询”三个维度分类。它们不是互斥标签，同一个注入点可能同时具备多种信号。

## 按观察信号分类

### 直接结果型

应用把被修改查询的结果直接放入响应。常见表现是返回行数、字段或页面内容发生稳定变化。

判定重点：

- 变化必须能由成对条件控制。
- 排除缓存、排序波动、权限差异和随机内容。
- 只证明结构可控，不继续读取无关业务数据。

### UNION 结果型

当原查询结果被返回，且注入位置、列数和类型兼容时，额外查询结果可能并入原结果。

知识重点：

- `UNION` 两侧结果形状需要兼容。
- “页面显示额外内容”是表现，根因仍是字符串构造破坏结构边界。
- 仅在公开实验室学习列数与类型概念，不对互联网目标枚举数据。

### 错误型

数据库或应用错误携带了结构、类型或数据线索。错误可能帮助确认上下文，但“出现错误”本身不是充分证据。

应区分：

- 语法错误：说明输入影响了解析，但仍需对照。
- 类型转换错误：可能只是合法绑定参数不符合类型。
- 详细数据库错误：同时构成信息泄露，但关闭错误页并不能修复注入。

### 布尔盲注

应用不返回数据库错误或查询结果，但响应内容、状态、长度或业务分支会随数据库条件真假稳定变化。

可靠证据需要：

- 一组逻辑上相反的条件。
- 多次重复得到一致分组。
- 基线请求证明差异不是登录态、限流或缓存造成。

### 时间盲注

响应内容不变，但数据库条件控制了服务器端延迟。网络抖动很容易制造误判，因此应使用多次样本、对照条件和明显高于基线波动的差异。

时间型验证只能在隔离靶场或明确授权环境进行，并设置短延迟、低次数和停止点，避免变成资源消耗测试。

### 带外信号

数据库或运行环境在查询执行时产生另一个网络或系统信号。它依赖数据库功能、网络出口和权限，风险高于普通差异验证。

本知识库只保留概念和公开实验室索引，不记录真实基础设施配置或外传步骤。

### 堆叠语句

部分数据库和驱动允许一次调用执行多条语句。是否成立取决于驱动配置和协议；不能仅凭数据库方言推断。

安全评估中不使用破坏性语句验证。能够证明第二条无害语句被解释已经足够，且只应在隔离靶场进行。

## 按查询位置分类

### 数据值位置

例如筛选条件、插入值、更新值。通常可以直接使用参数绑定，是最容易正确修复的一类。

### 标识符位置

例如动态表名、列名、Schema。普通值占位符通常不适用，应将业务选项映射为代码内固定标识符。

### 排序和方向位置

例如排序字段、升降序。安全实现是枚举映射，不是把任意字符串拼入 `ORDER BY`。

### 数量与分页位置

现代驱动通常可以绑定数值，但不同数据库、驱动和 ORM 的能力不同。即使转换成整数，也应使用参数 API 并设置业务边界。

### `IN` 列表

一个占位符通常代表一个值，而不是逗号分隔的一组值。安全做法是按元素数量生成固定数量占位符，并逐项绑定；空列表要单独定义语义。

### 存储过程和动态 SQL

过程参数本身不自动保证内部动态 SQL 安全。审计应继续追踪参数是否进入字符串拼接和动态执行接口。

## 按数据生命周期分类

### 一阶注入

输入在当前请求或任务中立即进入危险查询并产生影响，入口和执行点距离较近。

### 二阶注入

输入先被保存或转发，之后由另一个功能读取并拼入 SQL。最初写入可能完全使用参数化，因此只检查入口保存逻辑会漏报。

### 跨服务注入

服务 A 把数据当普通字段传给服务 B，服务 B 再不安全地构造 SQL。每个服务都必须把外部数据视为不可信，不能把“来自内部服务”当作安全证明。

## 判定证据分级

### 已验证

- 白盒：存在可达的数据流，外部输入未经结构隔离进入 SQL 执行点。
- 黑盒靶场：成对对照稳定证明输入改变查询结构。
- 修复复测：改为参数化后结构差异消失，正常功能保持。

### 代码推断

- 找到字符串拼接与执行点，但缺少可运行环境或输入可达性证据。
- 数据来自当前不可控源，但未来边界可能变化。

### 待环境验证

- 扫描器告警、错误关键词或单次响应差异。
- 无法确认数据库、驱动配置、缓存或中间层行为。

## 最小停止点

达到以下任一条件就应停止扩大验证：

- 源码数据流已证明可控输入改变 SQL 结构。
- 隔离靶场的成对条件产生稳定、可重复差异。
- 修复前后回归测试能够复现并阻断结构变化。

不需要读取真实用户数据、修改记录、执行系统命令或测试拒绝服务。
