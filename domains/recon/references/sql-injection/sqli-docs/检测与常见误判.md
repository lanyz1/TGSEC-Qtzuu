# 检测目标

检测应分别回答三个问题：

1. 是否有人提交了可疑输入？
2. 输入是否到达了不安全 SQL 构造点？
3. 查询是否成功改变了结构或产生了影响？

只有第 1 项通常只是尝试或噪声；第 2、3 项才逐步接近漏洞与事件确认。

# 代码层检测

## 高价值模式

- 外部输入参与 SQL 字符串连接、插值或格式化。
- ORM raw/literal API 接收可控字符串。
- 动态表名、列名、排序方向来自请求。
- 存储过程中把参数拼入动态执行文本。
- 从数据库、队列或文件读取的数据被二次拼接。
- 数据库封装函数同时接受“任意 SQL 字符串”和外部参数，却没有强制绑定契约。

## 静态分析注意点

- 识别框架的污点源、净化器和数据库 Sink。
- 不把任意类型转换都视为可靠净化。
- 参数绑定函数应作为结构隔离点，而不是普通字符串转义。
- 对 raw query、动态 SQL 和反射式查询构造提高优先级。
- 检查跨函数、跨模块和持久化后的二阶数据流。

# 运行时检测

## 应用日志

可记录：

- 请求关联 ID、路由和参数名称。
- 参数类型、长度、字符类别等摘要。
- 数据库异常类别和错误码。
- 查询模板 ID，而不是带敏感值的完整 SQL。
- 用户、会话或来源的速率与失败趋势。

不应记录：

- 口令、Token、私钥。
- 完整个人数据。
- 可能包含敏感信息的完整查询结果。
- 未脱敏的数据库连接串。

## 数据库审计

关注：

- 同一应用账号的语法错误和权限错误突增。
- 正常模板之外的新查询结构。
- 应用账号访问平时不使用的表、系统目录或管理功能。
- 读服务出现写入、DDL 或高权限操作。
- 查询时延和资源消耗的异常分布。

数据库日志需要与应用请求 ID、服务实例和部署版本关联，否则难以区分攻击、程序缺陷与运维操作。

## WAF、RASP 与网关

它们适合作为纵深检测和临时缓解，但存在：

- 编码与多层解析差异。
- 数据库方言差异。
- 合法搜索文本导致误报。
- 二阶注入不在当前请求中执行。
- 非 HTTP 输入无法覆盖。

规则命中应触发调查，不能代替源码修复。

# 行为信号

## 可能的探测行为

- 同一参数短时间出现大量细微变化。
- 响应真假模式与输入条件呈稳定相关。
- 请求耗时出现人为分组，而不是连续随机波动。
- 同一入口持续触发数据库语法或类型错误。
- 单一会话遍历多个字段、排序或分页组合。

## 可能的成功影响

- 非预期的大结果集。
- 认证或业务流程异常跳转。
- 应用数据库账号访问新对象。
- 数据修改量、导出量或查询复杂度异常。
- 数据库和应用同时出现关联异常。

# 常见误判

## 单引号触发 500

可能是：

- SQL 注入。
- 严格类型转换失败。
- 模板、JSON 或其他解析器错误。
- 程序自身未处理异常。

需要白盒数据流或成对对照才能定性。

## 响应内容改变

可能由搜索语义、缓存、A/B 测试、权限、排序不稳定或个性化造成。必须重复对照并控制会话与缓存变量。

## 响应变慢

网络、锁等待、连接池、冷启动和上游重试都可能造成延迟。时间型结论需要统计分离和逻辑相反的对照。

## 日志出现 SQL 关键字

用户可能在论坛、代码编辑器、搜索框或工单中合法输入 SQL 文本。关键字不是根因；应确认该字段是否进入查询结构。

## WAF 命中

WAF 规则通常优化召回率，命中不能证明后端存在注入。反之，未命中也不能证明后端安全。

## 参数化后结果范围扩大

例如 `LIKE` 中的 `%` 和 `_` 仍有通配语义。这通常是搜索业务设计问题，不代表参数改变了 SQL 结构。

# 调查流程

1. 保全请求 ID、时间、路由、服务版本和账号。
2. 确认异常来自哪个解析层或数据库。
3. 找到对应 SQL 模板和执行 API。
4. 判断数据是否作为参数绑定。
5. 复核数据库账号权限和实际访问对象。
6. 在隔离环境重放最小用例。
7. 将结论标记为已验证、代码推断或待环境验证。
8. 修复后使用同一证据链复测。

# 严重性因素

- 是否无需认证即可触达。
- 可读、可写的数据范围。
- 数据库账号权限。
- 是否影响多租户边界。
- 是否可通过后台任务触发二阶路径。
- 是否存在稳定回显或自动化放大条件。
- 是否有可靠检测、限流和审计。

不要仅根据“SQL 注入”名称固定评级；应以实际可达影响为依据。
