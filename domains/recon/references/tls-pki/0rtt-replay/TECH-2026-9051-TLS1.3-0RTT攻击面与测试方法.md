# 目标

本卡用于在自有、明确授权或隔离实验环境中评估 TLS 1.3 Early Data（0-RTT）。

目标不是收集真实票据或制作公网重放工具，而是证明或否定一条完整风险路径：

`0-RTT 已启用 → 请求可进入 Early Data → 反重放或回退边界失效 → 同一业务意图产生重复副作用`

只发现配置项、协议支持或可伪造请求头，不能直接写成重放漏洞。

# 固定决策闭环

`范围 → 基线 → 攻击面 → 单一假设 → 最低影响检查 → 证据 → 停止 → 修复 → 复测`

这是可审计的决策结构，记录判断依据而不展开无关内部推理。

## 1. 范围

开始前记录：

- 资产归属、环境、协议和组件版本。
- 允许查看的配置、源码、日志与本地 fixture。
- 是否允许 loopback 或容器中的单次恢复验证。
- 测试路由、合成对象、最大连接数和最大请求数。
- 禁区：生产、副作用路由、真实 session ticket、PSK、Cookie、用户流量、第三方目标、DoS。
- 停止方式和证据保存位置。

范围不完整时，只做公开文档、源码、配置和日志字段分析。

## 2. 基线

先建立四项事实：

1. TLS 1.3 当前根规范是 RFC 9846。
2. 0-RTT 不保证跨连接不可重放。
3. TLS 层直接复制与客户端重试造成的业务重复是两类问题。
4. HTTP 的 Safe、Idempotent、`Early-Data: 1` 和 425 不能替代业务副作用审计。

## 3. 数据流

至少画出：

`恢复凭据 → TLS/QUIC 接受决定 → 代理风险标记 → HTTP 路由策略 → 应用幂等 → 副作用`

每条边记录：

- 决策组件与版本。
- 输入来源和可信度。
- 状态作用域：进程、节点、区域或全局。
- 可观察日志。
- 失败时是拒绝、425、等待握手还是错误放行。

# 优先攻击面

## A. 启用状态与默认值

失败条件：

- 运营方认为 0-RTT 关闭，实际 downstream 已开启。
- 上层代理覆盖 TLS 库默认 AntiReplay。
- upstream 与 downstream 配置被混为一谈。

最低证据：

- 最终生效配置、组件版本、TLS 库版本和连接方向。

## B. 路由语义

失败条件：

- 仅按方法名允许 Early Data。
- 名义 GET 消费令牌、写数据库、发送消息或改变权限。
- PUT、DELETE 因“幂等”被误当作 Safe。

最低证据：

- 路由到副作用代码的调用链或合成计数器结果。

## C. 票据与反重放状态

失败条件：

- 只共享 ticket key，不共享票据已用状态。
- external PSK 或 external session cache 绕开预期的内建保护。
- cache TTL、ticket 有效期和接受窗口不一致。

最低证据：

- 状态模式、原子消费位置、作用域和故障行为。

## D. 多节点、重启与故障切换

失败条件：

- 同一恢复凭据可在多个节点各接受一次。
- 新实例把空缓存解释为全部新鲜。
- replay store 不可用时继续接受。

最低证据：

- 合成标签在不同实例的接受日志、启动代次和唯一业务计数。

## E. `Early-Data` 风险传播

失败条件：

- 代理删除、覆盖或降级已有风险标记。
- 源站把该头当成可信身份或“已去重”证明。
- 握手完成后错误清除前一跳的 Early Data 风险。

最低证据：

- 每个受信 hop 的规范化头、内部元数据和策略结果。

普通客户端可发送 `Early-Data: 1`。这本身不是漏洞；只有后端错误授予信任或绕过控制才构成边界失效。

## F. 425 与重试

失败条件：

- 425 后再次使用 Early Data。
- 代理无界 retry。
- 首次请求已产生副作用后才返回 425。

最低证据：

- attempt、握手阶段、状态码和业务提交顺序。

## G. QUIC 与 HTTP/3

失败条件：

- 把 packet number 去重当成跨连接防重放。
- 恢复 transport parameters 或 HTTP/3 SETTINGS 不兼容仍接受 0-RTT。
- Retry、CID 或 NEW_TOKEN 被当成业务幂等。

最低证据：

- 0-RTT 接受决定、恢复参数、stream 状态和业务日志。

## H. DTLS

失败条件：

- 把 record replay window 当成跨连接 Early Data 防护。
- Cookie、CID 或可达性检查被当成业务唯一性证明。

最低证据：

- epoch/记录序号结果与跨连接业务幂等结果分别记录。

## I. 观测

失败条件：

- 把“字段未采集”解释为 false。
- 日志只有 resumption，没有 Early Data 状态。
- 无法关联 attempt、配置代次、启动代次与业务副作用。

最低证据：

- `accepted|rejected|not_sent|unknown` 明确枚举。
- 合成 connection、ticket、ClientHello 与 idempotency 标签。

# 可证伪假设

每轮只验证一个假设，并同时写：

- `scope`：授权目标与禁区。
- `observation`：已知配置或行为。
- `hypothesis`：可能失效的单一边界。
- `expected_safe_behavior`：安全实现应如何处理。
- `minimum_check`：最低影响验证。
- `evidence_required`：足以支持或否定结论的证据。
- `stop_condition`：到点停止。
- `prohibited_actions`：禁止动作。

示例：

> 在两个共享测试 ticket key、但 replay state 独立的 loopback 实例中，同一合成恢复凭据可能各接受一次 Early Data。

反证条件：

- 第二实例拒绝 Early Data；或
- 共享状态原子拒绝重复；或
- 请求被延迟到握手后且没有重复业务副作用。

# 最低影响验证阶梯

1. 公开规范和版本化官方文档。
2. 配置、源码和日志字段静态审计。
3. dry-run、mock 源站或只读 echo。
4. loopback/容器、自签名证书、合成票据和一次性计数器。
5. 最多一次建票和两次串行恢复；得到证据即停。

禁止：

- 截获或保存真实用户流量。
- 获取生产 ticket、PSK、Cookie、key log 或私钥。
- 向公网或第三方发送重放。
- 并发重放、压测、绕过反重放、DoS、持久化。
- 用支付、认证、余额、权限或消息投递作为测试副作用。

# 决策类型

- `pause_for_scope`：范围不足，暂停主动检查。
- `analyze_only`：只能给出源码或配置推断。
- `allow_minimal_check`：允许一次隔离、可回滚的最低影响验证。
- `stop`：证据已足够或下一步会越界。
- `report_not_a_finding`：控制按预期生效，没有可观察副作用。

# 证据等级

- `verified`：授权隔离环境中可重复观察到边界失效和副作用。
- `inferred`：配置或源码显示可达风险，但未完成运行态验证。
- `unverified`：只有猜测、扫描信号或厂商未公开状态。
- `not_a_finding`：安全拒绝、425 回退或业务幂等按预期工作。

严重度由副作用决定：

- 只支持 0-RTT：信息项。
- 重复只读请求，无额外影响：加固项或低风险。
- 重复可回滚低价值动作：中风险。
- 认证、权限、资金、秘密或跨租户副作用：高风险，但不得用真实高风险对象验证。

# 停止条件

出现任一条件立即停止：

- 已观察到一次合成重复副作用。
- 已观察到确定性拒绝且没有副作用。
- 下一步需要真实凭据、生产数据、第三方流量或提高并发。
- 日志无法保存、状态异常或范围发生变化。
- 请求、连接、时间或深度达到预算。

# 修复顺序

1. 不需要 0-RTT 就关闭。
2. 按路由显式允许，敏感路径永不提前执行。
3. 恢复或实现正确的单次票据/ClientHello 记录。
4. 明确跨节点权威状态与启动保护窗口。
5. 风险标记只升不降，并与外部可控头分离。
6. 425 后仅非 Early Data 重试且有 attempt 上限。
7. 业务层使用原子幂等、结果复用和对账。
8. 日志区分未知、未发送、接受、拒绝和副作用。

# 复测

复测同时验证：

- 原风险路径被确定性阻断。
- 节点切换、重启和状态故障不能重新打开窗口。
- 425 后不再发送 Early Data。
- 伪造风险头只能提高限制，不能获取权限。
- 正常 1-RTT 与允许的只读请求仍可用。
- 业务副作用总数符合预期。

# 记录边界

记录只包含观察、假设、最小检查、证据、停止点、修复与复测。所有对象、域名、票据标签和副作用均使用虚构或合成值。
