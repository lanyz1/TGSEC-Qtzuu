# WebSocket 与 SSE 授权安全评估

本专题用于在**自有系统、明确授权目标或隔离环境**中学习 WebSocket 与 SSE 安全评估。公开标准和教学资料只能证明来源可引用，不能证明任何测试目标已授权。

## 专题准入门

内容必须直接依赖 WebSocket/SSE、`Origin`、消息或订阅、帧或压缩、`EventSource`、`Last-Event-ID`、`retry` 或 `204` 等协议边界。删除这些边界后仍完整成立的通用内容不进入本专题；通用授权原则只作为具体攻击面的约束字段，不单独扩写。

## 唯一学习链

`范围 → 攻击面 → 假设 → 最低影响检查 → 证据 → 停止 → 修复 → 复测`

1. **范围**：先确认资产所有权、书面授权、允许端点、测试身份、时间窗和明确禁区。
2. **攻击面**：只从十二个 WebSocket/SSE 协议相关攻击面中选择当前目标实际存在的一项。
3. **假设**：把风险写成一个可观察、可证伪的单变量命题，不把扫描提示直接当成漏洞。
4. **最低影响检查**：默认只在本地夹具主动验证；对明确授权目标仍执行一个合法对照和一个单变量变体。
5. **证据**：优先使用代码、配置、路由、非敏感日志和合成数据，记录可复核事实而非私有思维链。
6. **停止**：一旦控制是否生效已有足够证据，或出现敏感数据、业务副作用、范围不清、资源异常，立即停止。
7. **修复**：修正协议边界的根因，不用 TLS、客户端隐藏或网关默认行为替代应用控制。
8. **复测**：复用原对照与原单变量变体，先确认合法路径，再确认风险路径，不扩大范围。

## 硬边界

- 主动验证默认仅限本地夹具；明确授权目标也不得超出文档清单中的连接和合成消息预算。
- 禁止 DoS、洪泛、压测、真实凭据、跨租户枚举、真实敏感数据读取和任何业务副作用。
- 不提供可运行利用代码、攻击载荷或危险参数；无法用最低影响方式验证时，结论只能是 `inferred` 或 `unverified`。
- `verified`、`inferred`、`unverified`、`not_a_finding` 必须严格分开，公开来源本身不能把发现提升为 `verified`。
