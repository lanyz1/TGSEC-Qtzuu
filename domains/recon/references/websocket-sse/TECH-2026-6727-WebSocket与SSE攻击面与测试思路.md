# 攻击面与测试思路

本地图只用于自有系统、明确授权目标或隔离环境中的安全评估。`public_sources` 仅说明依据来自公开资料；任何主动检查都必须另有 `authorized_targets_only` 范围。

每次评估只选择一个实际存在的攻击面，形成一个可证伪假设，并按授权验证清单执行一个合法对照与一个单变量变体。无法在预算内取得直接证据时停止，将状态标为 `inferred` 或 `unverified`，不得扩大动作。

专题准入门：删除 WebSocket/SSE、`Origin`、消息/订阅、帧/压缩、`EventSource`、`Last-Event-ID`、`retry`/`204` 等协议边界后仍成立的通用内容，不单独扩写。

## 01. HTTP/1.1、HTTP/2、HTTP/3 握手识别一致性

- **观察信号**：同一 WebSocket 业务同时出现 `101 Upgrade`、HTTP/2 或 HTTP/3 Extended CONNECT，但资产清单、网关规则或拒绝日志只覆盖其中一种。
- **可检验假设**：所有实际启用的握手形式最终进入同一来源、认证、子协议、扩展、资源与日志策略；传输差异不会形成旁路。
- **最低影响证据**：先只读映射路由；主动阶段只在一个已授权疑似路径建立一个合法对照和一个仅改变来源或子协议决策输入的握手，不发送业务消息。
- **常见误报**：Extended CONNECT 本来就没有 HTTP/1.1 的 `101`、`Upgrade` 或连接级字段；缺少这些标志不能单独证明端点或控制缺失。
- **停止点**：确认策略入口等价，或定位一个具体缺失入口即停；不得继续枚举主机、端口、ALPN 或未声明传输。
- **修复复测**：把受支持握手汇聚到统一安全入口，只复测原疑似路径的原对照与原单变量变体。

## 02. CSWSH 与完整 Origin 决策

- **观察信号**：浏览器握手自动携带会话，服务端只比较 Host、子串或宽松后缀，或把 CORS、TLS、`Sec-WebSocket-Key` 当成来源与身份控制。
- **可检验假设**：浏览器路径按标准解析后的完整 `scheme + host + port` 精确允许，异常来源不能借自动凭据获得敏感通道，且 Origin 不替代认证与逐消息授权。
- **最低影响证据**：来源校验代码、非敏感决定日志、一个允许来源握手和一个仅替换为预置未允许来源的握手；连接后不发送业务消息。
- **常见误报**：非浏览器客户端能自定义或不发送 Origin 是协议预期；若其入口隔离且有独立认证，不能单独定性为 CSWSH。
- **停止点**：允许/拒绝和独立认证边界已确定即停；不得制作跨站页面、借用真实会话或继续尝试来源组合。
- **修复复测**：使用完整 Origin 精确允许列表，异常来源默认拒绝，并复测原两个来源。

## 03. 长连接会话撤销与能力收窄

- **观察信号**：连接只在握手读取角色，登出、禁用、改密、撤销或降权后仍可执行敏感消息或保留订阅。
- **可检验假设**：会话或权限变化会关闭连接或立即收窄能力；敏感动作读取当前授权，关闭路径释放订阅和连接映射。
- **最低影响证据**：状态机与撤销传播代码、一个撤销前无副作用只读动作，以及只改变合成会话状态后重复同一动作的结果。
- **常见误报**：正常会话刷新延续同一主体和权限，不等同于撤销失效；边缘连接仍在也不代表应用订阅仍有效。
- **停止点**：撤销后同一动作的决定与资源状态已确定即停；出现真实账号变化、敏感响应或写入立即停止。
- **修复复测**：维护会话到连接的可撤销映射，敏感动作回源复核，只复测原撤销前后动作对。

## 04. 逐消息与订阅对象授权

- **观察信号**：连接认证后不再鉴权，消息直接信任客户端对象或租户，`subscribe`、`join`、room、topic 被当成无害配置。
- **可检验假设**：每条消息和持续订阅都按当前主体、租户、对象、动作和业务状态授权，失权时撤销既有订阅。
- **最低影响证据**：服务端授权位置、一个预置合法合成对象和一个预置未授权对象的同类型只读消息；不猜测第三个标识。
- **常见误报**：公开主题或主体自有对象按产品策略可读；客户端可提交对象 ID 本身不是越权证据。
- **停止点**：两个预置对象的允许/拒绝已确定即停；收到其它对象数据、广播、存在性差异或写入立即停止。
- **修复复测**：在查询、广播和订阅创建前执行对象级授权，只复测原对象对及订阅清理。

## 05. WebSocket 消息与 SSE 事件的解析、授权和 Sink

- **观察信号**：WebSocket `message type/payload` 或 SSE `event name/event.data` 进入错误解析器，类型 Schema 通过后直接查询或广播，或事件数据未经上下文处理进入 HTML、URL 等 Sink。
- **可检验假设**：协议消息分派、类型专属 Schema、当前对象授权和最终上下文安全 API 各自独立生效，任一失败都在副作用前终止。
- **最低影响证据**：选定一个实际存在的 message type 或 event name，先用合法 payload/event.data 对照，再只改变其中一个无害字段；不退化为普通 REST 输入检查。
- **常见误报**：消息协议明确允许且安全忽略扩展字段，不等于解析绕过；`event.data` 中的标记字符按文本呈现不等于注入。
- **停止点**：变体进入错误协议处理器、触发越权读取、解释执行、外连、查询、写入或广播时立即停止。
- **修复复测**：封闭 message type/event name 分派，为各 payload/event.data 建立独立 Schema，并只复测原协议分支。

## 06. 分片重组与压缩后资源预算

- **观察信号**：只限制单帧或压缩前字节，未限制重组总量、碎片数、时间、未完成消息、解压结果、CPU 或失败清理。
- **可检验假设**：便宜检查先于昂贵解析，预算覆盖重组及解压后的结果，失败后重组和压缩上下文归零。
- **最低影响证据**：优先审查代码和配置；只有微型夹具明确给出小预算时，比较一个短小合法消息和一个仅超测试预算一个微小单位的变体。
- **常见误报**：分片或 `permessage-deflate` 协商是协议能力；有累计预算、秘密隔离和清理时，能力存在本身不是漏洞。
- **停止点**：任何资源指标异常、延迟上升或需要放大输入即停；不得寻找系统极限。
- **修复复测**：限制帧、重组、碎片、时间、并发和解压结果，继续只用原微型输入复测。

## 07. 应用背压与慢消费者治理

- **观察信号**：标准 WebSocket API 或服务端队列无应用预算，只依赖传输流控，慢消费者下队列持续增长或关闭后不释放。
- **可检验假设**：队列按字节、消息数和最老等待时长有界，达到边界后按消息语义等待、合并、丢弃、重同步或断开并最终归零。
- **最低影响证据**：队列配置与治理分支；隔离夹具内一个正常消费对照和一个只暂停一个受控节拍的变体，每个连接最多三条相同短消息。
- **常见误报**：`bufferedAmount` 或队列瞬时非零但在预算内回落，不等于背压失效。
- **停止点**：队列跨过预设单步边界、持续增长、影响其它连接或需要更多消息时立即停止。
- **修复复测**：建立分层有界队列和明确治理动作，用原三条消息与原节拍复测资源归零。

## 08. 握手后消息与生命周期遥测

- **观察信号**：HTTP 日志只记录握手，无法关联消息接受、授权拒绝、订阅变化、队列、异常关闭和资源释放，或日志反而保存完整秘密与正文。
- **可检验假设**：握手后事件以稳定、低基数、非敏感字段关联，能说明决定和清理，又不记录 Cookie、Token、会话值或原始敏感消息。
- **最低影响证据**：字段字典和脱敏规则；同一合成连接内一个接受事件、一个预置拒绝事件及关闭状态。
- **常见误报**：不记录消息原文是正确最小化；只要决定、原因、关联和关闭状态可复核，不构成遥测缺失。
- **停止点**：发现真实凭据、个人数据、真实资源标识或需要扩大日志时间窗时立即停止。
- **修复复测**：补齐稳定事件与低基数指标、删除敏感原文，只复测原合成事件序列。

## 09. SSE 凭据化 CORS、Bearer Access Token 与缓存边界

- **观察信号**：凭据化 EventSource 使用宽泛来源、Bearer Access Token 出现在页面 URL/query，或个性化流可被共享缓存跨主体或 Origin 复用。
- **可检验假设**：凭据化流只允许确切 Origin，Bearer Access Token 不进入页面 URL/query，事件按当前主体授权，个性化响应具有明确私有缓存边界。
- **最低影响证据**：CORS、凭据位置和缓存配置；一个允许来源空流对照和一个仅改变为未允许合成来源的元数据结果。
- **常见误报**：明确公开、无凭据、无个性化内容的 SSE 使用星号来源，不能按凭据化 CORS 缺陷处理。
- **停止点**：出现真实凭据、个性化事件、跨主体缓存迹象或额外重连立即停止。
- **修复复测**：联合修复精确来源、短期凭据、当前事件授权与私有缓存，只复测原两个来源。

## 10. SSE `event.data` 不可信输入与安全呈现

- **观察信号**：客户端因数据来自 EventSource 就信任其为 HTML、URL 或已验证对象，跳过严格解析和最终上下文安全 API。
- **可检验假设**：`event.data` 始终按不可信字符串处理；约定 JSON 严格解析，纯文本按字面呈现，其它 Sink 使用各自安全构造方式。
- **最低影响证据**：只读数据流；隔离 UI 夹具中一个普通文本和一个仅增加不可执行标记字符的事件。
- **常见误报**：输入含标记字符但最终按文本呈现且无导航、外连或执行，不构成注入。
- **停止点**：出现解释执行、导航、外连、持久化、错误扩散或需要增强标记时立即停止。
- **修复复测**：按事件类型严格验证并使用上下文安全 API，只复测原普通文本与原惰性标记。

## 11. `Last-Event-ID` 恢复游标与当前授权

- **观察信号**：服务端把游标当身份，未绑定当前主体、租户、主题和保留窗口，恢复查询不重做授权或用差异错误泄露存在性。
- **可检验假设**：游标长度和格式受限，每次恢复按当前授权过滤，合法、错属、过期和畸形状态有一致且不泄露的处理策略。
- **最低影响证据**：一个由夹具提供的合法游标和一个预置错属游标；只比较两次恢复决定，不猜测第三个值。
- **常见误报**：当前主体合法游标被接受并只返回其授权范围内事件，是正常恢复行为。
- **停止点**：返回其它主体事件、真实历史数据、存在性差异或自动额外重连立即停止。
- **修复复测**：绑定游标上下文并在恢复前重做当前授权，只复测原两个合成游标。

## 12. SSE 自动重连、`retry`/204 与本地资源控制

- **观察信号**：204 后仍建连，或正常 client close/204 路径遗留订阅、心跳、队列与计时器；暂态重试没有本地工程预算。
- **可检验假设**：WHATWG 语义下 204 停止重连；有界次数、退避、抖动与实际连接预算属于本地工程控制，所有关闭路径进入同一幂等清理。
- **最低影响证据**：第一个实际连接执行正常 client close 合法对照，第二个只把终止方式改为 204；两条路径均不投递事件，任何额外自动重连也计入连接数并触发停止。
- **常见误报**：标准自动重连或一次本地有界重连本身不是漏洞；不能把本地次数、退避、抖动写成 WHATWG 规范要求。
- **停止点**：出现任何额外自动重连、第三个实际连接、资源计数上升或需要延长观察时立即停止。
- **修复复测**：保持标准自动重连、`retry` 解析与 204 语义，另由本地工程设置连接预算并统一 client close/204 清理，只重复原两个关闭路径。
