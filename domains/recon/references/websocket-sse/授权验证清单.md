# 授权验证清单

本清单只适用于自有系统、明确授权目标或隔离环境。公开来源可用于建立假设，但不授予测试目标权限。主动验证默认仅在本地夹具执行；对明确授权目标也必须遵守同一最低影响预算。

专题准入门：如果删除 WebSocket/SSE、`Origin`、消息/订阅、帧/压缩、`EventSource`、`Last-Event-ID`、`retry`/`204` 等协议边界后，某项检查仍完整成立，则它不作为本专题独立 finding。

## 一、执行前

### 授权与范围

- [ ] 已把环境标记为 `local_fixture`、`self_owned` 或 `explicitly_authorized`；未满足其中一项则不主动验证。
- [ ] 已记录目标所有者、授权引用、允许的域名/端点/协议、测试时间窗、测试身份和明确禁区。
- [ ] 已明确写出：`public_sources` 只用于知识依据，当前目标必须单独满足 `authorized_targets_only`。
- [ ] 已确认代理、CDN、HTTP/1.1 Upgrade、HTTP/2/3 Extended CONNECT 和 SSE 路径中哪些实际在范围内；未知路径不探测。
- [ ] 已确认只使用合成账号、合成资源、合成事件和无副作用动作；没有真实凭据或真实敏感数据需求。

### 假设与准入

- [ ] 当前任务只选择攻击面地图中的一个编号，不并行扩展到相邻攻击面。
- [ ] 假设写成可观察、可证伪的单句，明确预期控制、唯一变化变量和可接受证据。
- [ ] 已准备一个合法对照和一个单变量变体；两者除待检变量外保持相同。
- [ ] 合法对照证明正常 WebSocket/SSE 路径可用，单变量变体只判断目标控制是否生效。
- [ ] 已先检查代码、配置、路由、单元夹具和非敏感日志；只有静态证据不足时才考虑主动验证。
- [ ] 已设定停止点：获得足够证据、出现敏感内容、发生副作用、资源异常、范围不清或授权不明时立即停止。

### 强制预算与禁区

- [ ] 整项主动验证最多使用 **两个实际连接**；浏览器自动重连同样计入，任何第三个连接都触发停止。
- [ ] 每个连接最多处理 **三条合成消息或事件**；握手、CORS、缓存或关闭元数据足以判断时为零条。
- [ ] `Last-Event-ID` 只允许预置合法游标和预置错属游标各一次，恰好占用两个连接；不得尝试第三个值。
- [ ] SSE 重连策略优先静态审查或单元夹具；若一次自动重连已占满两个实际连接，本轮不得再执行其它连接对照。
- [ ] 不执行 DoS、洪泛、压测、容量探测、持续慢连接、重连风暴、解压炸弹或压缩侧信道采样。
- [ ] 不使用真实凭据，不借用他人会话，不读取真实事件流，不执行写操作或其它业务副作用。
- [ ] 不做跨租户枚举；对象或游标授权只使用授权方预置、名称已知的合成可见/不可见夹具。
- [ ] 不提供或运行利用代码、攻击载荷、危险参数、批量脚本或自动扩展变体。

## 二、验证中

### 执行顺序

- [ ] 先执行合法对照并记录结果，再执行唯一的单变量变体；对照失败时停止，不把变体结果解释为安全控制。
- [ ] 每次动作前复核当前连接数和该连接已发送的合成消息数，不突破既定预算。
- [ ] 只观察握手状态、协商元数据、非敏感拒绝原因、合成事件标记、连接状态和匿名化资源指标。
- [ ] 不因第一个变体结果含糊而追加第二个变量；证据不足时转为 `unverified`。
- [ ] 若只能从代码、配置或日志推断运行时影响，不伪装成主动验证，候选状态只能为 `inferred`。

### WebSocket 专项

- [ ] `Origin` 检查只比较一个允许来源对照和一个不允许来源变体，不遍历域名、端口或编码形式。
- [ ] 握手认证检查不使用真实 Token、Cookie 或会话；协议随机字段、子协议和扩展不被当作身份。
- [ ] 消息/订阅授权只使用预置合成资源，不猜测资源 ID，不接触真实租户数据。
- [ ] 帧、重组、编码和压缩边界优先使用单元夹具；线上授权目标不逐步放大输入、不测资源极限。
- [ ] 会话撤销只改变合成会话状态，后续最多使用一条无副作用消息确认旧连接能力。
- [ ] 队列、背压和慢消费者优先审查配置与指标；少量合成消息无法验证阈值时保持 `inferred`，不增加流量。

### SSE 专项

- [ ] CORS/凭据检查只比较一个允许来源页面和一个不允许来源页面，事件内容仅为合成公开标记。
- [ ] 缓存检查只观察响应头、配置和非敏感缓存日志，不尝试让不同真实主体复用事件流。
- [ ] `Last-Event-ID` 最多使用两个预置值：一个有效游标和一个失效或错属游标；不猜测、不递增、不枚举。
- [ ] 运行时重连检查若经历一次断开—重连周期，即已用完两个实际连接；记录当前授权是否重新执行后停止。
- [ ] `retry` 与 `204` 优先用标准语义、静态证据和本地单元夹具判断；`204` 主动对照只与正常 client close 比较，不先制造暂态重连。
- [ ] `event.data` 的客户端 Sink 使用惰性文本标记验证，不使用脚本、外连或可执行内容。

### 即时停止

- [ ] 看到非预期真实数据、其他主体信息、私密事件正文或可用凭据时，已立即停止并最小化保留证据。
- [ ] 发生写入、通知、扣费、权限变化、下游调用或其它副作用时，已立即停止并按授权联系人流程报告。
- [ ] 出现延迟、CPU、内存、队列、连接数或错误率异常时，已立即停止，不通过增加流量确认。
- [ ] 目标跳转到范围外主机、代理改变目标、授权边界无法核实时，已立即停止。
- [ ] 结论所需证据已经取得时，已停止而非继续扩大覆盖。

### 证据卫生

- [ ] 证据只保留时间、端点类别、协议路径、规范化来源、合成主体/资源标识、结果、策略版本和必要日志引用。
- [ ] Cookie、Token、会话 ID、URL 票据、原始游标、真实消息正文和个人数据均已删除或不可逆脱敏。
- [ ] 已分别标注证据类型：`runtime`、`unit_fixture`、`code`、`config` 或 `log`。
- [ ] 已记录对照与变体的唯一差异、观察结果和停止原因，使第三方无需私有思维链即可复核。

## 三、结论

每个候选 finding 必须且只能使用以下一个状态；状态与严重度分开记录。

- **`verified`**：在本地夹具、自有系统或明确授权目标中，合法对照和单变量变体产生可复现的直接证据，且执行未越过预算。公开资料、扫描提示或代码猜测不能单独得到此状态。
- **`inferred`**：代码、配置、路由或非敏感日志清楚支持该风险，但缺少允许范围内的直接运行时对照。必须写明推断链的公开依据和缺失的验证证据。
- **`unverified`**：假设尚未执行、证据不足、结果冲突、对照失败或所需动作超出授权/预算。不得把“看起来可能”写成已确认影响。
- **`not_a_finding`**：合法对照可用，单变量变体被预期控制拒绝，或已确认设计不暴露该协议边界。它不是“没有测试”的替代状态。

### 结论检查

- [ ] 每个 finding 恰好选择一个状态，没有混写“部分 verified”或用置信度替代状态。
- [ ] `verified` 附合法对照、单变量变体、直接观察和停止点；四项缺一则降级。
- [ ] `inferred` 明确哪些是事实、哪些是推断，以及哪项最小证据仍缺失。
- [ ] `unverified` 明确阻点，不建议通过扩大连接、消息、游标或租户范围解决。
- [ ] `not_a_finding` 有控制生效证据，不把超时、网络失败、空响应或对照失败当成安全。
- [ ] 影响只描述已观察到的 WebSocket/SSE 边界，不外推到未测试端点、协议版本、主体或租户。
- [ ] 报告只输出可审计事实、简短判定依据和不确定性，不输出私有思维链或隐藏推理过程。

## 四、复测

- [ ] 修复说明指向根因控制：WebSocket/SSE 路由、Origin、认证、状态机、消息/订阅授权、帧/压缩、SSE CORS/缓存或重连游标。
- [ ] 复测范围与原 finding 相同，不新增端点、账号、协议版本、资源、Origin 或游标。
- [ ] 仍使用原合法对照和原单变量变体，仍遵守最多两个实际连接、每连接最多三条合成消息或事件。
- [ ] 先确认合法对照没有回归，再确认原变体被预期控制拒绝或安全处理。
- [ ] 会话、订阅和游标修复同时核对当前授权；帧、压缩和队列修复优先在本地单元夹具完成。
- [ ] 已确认拒绝日志和遥测不泄露凭据、敏感正文或可枚举差异。
- [ ] 复测通过时附新证据并保留原证据引用；复测失败时停止，不追加新变体。
- [ ] 修复改变了攻击面或假设时，关闭原复测并重新走执行前清单，不在本轮隐式扩展。
