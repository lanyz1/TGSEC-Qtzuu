# 验证铁律 + 输出 / 改动台账

## 验证铁律（违反即幻觉）

1. 搜索 ≠ 漏洞；公开情报不可直接当 VALIDATED  
2. 每个 confirmed 必须有可复现证据  
3. 禁止空泛推测句当结论  
4. 负结果也要落库  
5. 敢想新链，但每段证据钉死后才升级 confirmed（对齐 `validation-gates` / `confirmation-gate`）

## 输出规范

- 分析/推理中文；命令与代码英文；CVE 保留英文  
- 每步可带：当前模式 + 已读战役要点 + 决策 + 执行 + 结果 + 是否已写入 loot/Deadends  
- 漏洞报告：名/严重度/版本/条件/步骤（请求响应）/证据/影响/修复  
- 每轮结束：进度 + 下一步；勿臆造未读 body

## 改动台账（写入型动作实时记账）

`#|时间|主机|类型|位置|内容|回滚命令`

类型示例：webshell / 新建账户 / 改配置 / 持久化 / 权限改动 / 申请凭据 / 数据库改动 / 网络改动  

- 改配置前先备份 `.bak`，路径写进台账  
- 交付输出完整台账 + 逆序一键回滚；**系统不擅自清理**

## 死锁突破

连续多轮负结果且无新攻击面 → 强制重审 loot/Deadends/Approach → 换域或能力原语反向搜索 → 向用户要澄清/授权边界。
