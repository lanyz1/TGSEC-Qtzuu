# roles.d/ —— 角色提示词（自填）

这个目录**故意是空的**。每个角色一个 `.md`，文件名 = 角色 code：

| 文件 | 角色 | 职责 |
|---|---|---|
| `plan.md` | 主会话（指挥） | 计划、派活、核对落库、汇报 |
| `recon.md` | 信息收集 | 域名/子域/端口/指纹/OSINT |
| `assess.md` | 资产梳理 | 资产入库、价值评估、攻击面排序 |
| `vuln-scan.md` | 漏洞发现 | 漏洞探测、验证、入库 |
| `exploit.md` | 漏洞利用 | 拿权限、WebShell、提权 |
| `internal.md` | 内网渗透 | 隧道、横向、凭据、域 |

## 怎么写

UTF-8 纯文本 / Markdown，直接写你的提示词正文。例：

```
# 信息收集

## 你是谁
你负责被动与主动信息收集，产出可入库的资产清单。
动手前先 `purge_preflight(target)`；结果一律 `purge_asset_add` 落库，**没落库的不算成果**。

## 开工动作
1. 被动：证书透明度、DNS、搜索引擎、公开代码库
2. 主动：端口扫描、指纹识别、目录爆破
3. 每拿到一个资产立刻入库，别攒到最后

## 产出
- 资产：ip / port / service / fingerprint / source
- 交给 `assess` 做价值排序

## 边界
- 只碰目标清单内的资产
- 拿不准就停下来问人，不要自己扩大范围
```

## 生效

- 存盘即生效：`purge_role_prompt("recon")` 下次调用读到新内容。
- 也可调 `purge_role_prompt_reset` 强制重载。
- 改完重启网关最稳（插件按会话缓存运行时）。

## 查状态

```
purge_roles          # 列出六个角色，看每个是否已填（custom: true/false）
purge_role_prompt    # 取某个角色稿全文
```

`commander_brief()` 会在角色没填时打 ⚠ 标记提醒你。

## 为什么要自己写

角色提示词是**战术资产** —— 决定 agent 怎么思考、先做什么、什么时候停手。
本插件只给**骨架**（角色划分、取稿机制、台账接口），
内容由你按自己的方法论填。填得好坏，直接决定 agent 的表现。
