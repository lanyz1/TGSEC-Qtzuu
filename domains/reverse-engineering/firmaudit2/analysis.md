# FirmAudit2 — 固件审计流水线要点 (源自 README)

- 定位: 让 Agent 挖到的固件漏洞可回放/可校验/可交付; 三层约束 = 过程约束(8 段引导逐段校验, 段落表同时驱动提示词/校验规则/报告章节) + 结果约束(四道门) + 运行时约束(会话级 overlay 临时根 + 单次工具调用级活性看护)
- 八段式引导: 漏洞信息 → 漏洞描述 → 代码分析步骤 → 代码位置 → 复现步骤 → PoC/Exp 脚本 → 证据文件 → 修复建议; 校验不通过时打回原因拼进下一次引导, 回执按原名留在资料夹
- 四道结果门: ①收口门(引导未填完不许判定完成, 待补清单写入任务状态, 一小时后可接着填) ②本地仿真验证硬门(证据须同时出现"目标被起来"+"目标给出结果"两类运行时痕迹, 静态看出危险调用不算验证) ③CNVD 资产证明门(版本信息须由命令在复现前两个编号步骤内给出) ④报告复核门(正文与结构化字段逐条对账, 复核通过后再改正文会重开门, 上限 2 次)
- 运行环境: 会话级 overlay 临时根(回合结束销毁, /workspace 绑定失败直接退出不静默降级); 会执行任意命令的沙箱不接触宿主盘; 离线工具链+国内镜像; 看护阈值 = 工具调用静默 15 分钟/会话静默 30 分钟(阈值取自实测: 419 次已完成调用中最长 16.2 与 15.6 分钟, 均为全盘扫描); 任务状态落盘, 重启不打断在跑审计
- 实测(README 表格): 5 漏洞并行下发首段=0 入库全无回应; 4 并行+校验回环=4 条卡第 2 段失败; 单漏洞串行=8/8 段 6 分 48 秒填齐; 串行+8 段+回执+送达判定=3 漏洞 24/24 段(7 次打回+1 次判丢重投)
- 交付形态: 一漏洞一档的 CNVD 复现资料总包(材料平铺包根; 固件保留上传原文件名以便脚本定位; 复现步骤到命令级; Markdown 唯一正文, Word 由其转换; 交付包按内容哈希去重, "该进包却没进"的材料连同原因登记)
- 获取: 闭源商业软件, 设备绑定离线授权(单设备永久); 前置 Windows 11 x64 + WSL2, 磁盘建议 ≥40GB, 大模型 API 自备; 前端基于上游开源项目 CTF-BTFly(获授权闭源商用)
