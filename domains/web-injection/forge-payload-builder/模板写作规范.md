# Forge 模板写作规范

> 这个项目里**数据是主体**——数据行数是引擎代码的两倍，而且引擎四轮漏洞类型铺开只涨了约 300 行。
> 加模板不是"填空"，是**提供一条你确认过可用的载荷**。

---

## 1. 快速开始

```bash
python new_template.py sqli.postgresql.union.dump --name "PostgreSQL UNION 读库名" \
  --ctype sql-expression

# 1. 填模板里的 TODO
# 2. 手算黄金样本的期望值填进 golden/
python validate_rules.py     # TODO 没填完这里会报错，是正常的
python run_golden.py
```

脚手架**只追加、不重写**已有文件。这一点是刻意的：本项目出过一次批量改数据的脚本
因为一个标志写错、静默丢掉两个文件全部修改的事故。追加比往返解析安全，也不动注释和排版。

也可以手写——下面的规则校验器都会帮你兜住。

## 2. 文件与 id

**按漏洞类型分目录，文件名即 id 前缀。**

| 文件 | id 必须以这个开头 |
| --- | --- |
| `data/sqli/mysql.yaml` | `sqli.mysql.` |
| `data/rce/linux.yaml` | `rce.linux.` |
| `data/deser/java.yaml` | `deser.java.` |

由 `validate_rules.py` 强制。新组件就新建文件。

## 3. 字段

### 必填

| 字段 | 说明 |
| --- | --- |
| `id` | 见上。全局唯一 |
| `name` | 显示名，出现在列表里 |
| `vuln` | 漏洞类型列表，如 `[sqli]` |
| `content_type` | **载荷文本的语法**。完整枚举见方案 §7；概念区分见方案 §3 |
| `body` | 载荷本体 |

### 常用

| 字段 | 说明 |
| --- | --- |
| `desc` | 一句话说清**什么时候用它、什么时候别用**。列表里直接展示 |
| `component` | 适用组件，如 `[mysql, mariadb]`。空列表 = 通用 |
| `version` | 朴素区间语法 `>=5.0` / `>=5.1 <5.7.9` / `*` |
| `slots` | 有限选项，见 §4 |
| `vars` | 自由文本变量，见 §4 |
| `requires` | **必须来自受控词表**，见 §5 |
| `status` | `golden` / `lab` / `theory`，按**实际验证程度**诚实填 |

### 两个容易放错地方的

- **版本信息放 `version`，不要塞进 `requires`**。曾经有模板把「9.3 及以上」写成前提，
  收敛词表时才发现——版本区间本来就有专门的语法。
- **`requires` 只写「载荷生效的必要条件」**，不写「什么时候想用它」。
  「点号被过滤」是后者（→ 用 `weak-filter`），「页面有回显位」是前者（→ `echo`）。

## 4. 占位符语法

| 写法 | 含义 | 求值时机 |
| --- | --- | --- |
| `<<name>>` | 字符串槽位 或 自由变量 | 变量替换阶段 |
| `<<slot.field>>` | 字典槽位的字段（一组值必须联合选择） | 槽位填充阶段 |
| `<<len(name)>>` | `name` 的**字节**长度 | 变量替换阶段 |
| `<<select(cols,pos[,expr])>>` | 生成带回显位的列清单，见下 | 变量替换阶段 |
| `<<rep(n,item)>>` | 把 `item` 重复 `n` 次 | 变量替换阶段 |
| `<<phpser(spec)>>` | 把 PHP 结构描述补成合法序列化串，见下 | 变量替换阶段 |
| `<<payload>>` | 嵌套内层载荷 | 变量替换之后 |

计算型占位符（`len` / `select` / `rep`）的参数查找规则是同一条：
**先按名字查（槽位 / 变量 / 字典槽位字段），查不到就当字面量**。
任何一环没填就**原样透传**（契约 3），不猜。
`<<phpser>>` 是个例外——它**只认名字**，不接受字面量，理由见下。

### `<<select(cols,pos[,expr])>>` —— 列数与回显位

联合注入的两种基本形态：

```
<<select(cols,pos)>>                 cols=3 pos=1  →  "1,2,3"
<<select(cols,pos,expr)>>            cols=3 pos=2  →  "1,@@version,3"
<<select(cols,pos,pg_read_file('x'))>> cols=3 pos=2 →  "1,pg_read_file('x'),3"
```

- **前两个参数是名字**（槽位、变量，或字典槽位的字段），值必须是数字。校验器强制它们可解析
- **第三个参数先按名字查**，查不到就当**字面量**用。所以带包装的表达式可以内联写，
  不必为它单开一个槽位。只按**前两个逗号**切分，表达式里的逗号（`concat(a,b)`）
  和括号（`pg_read_file('x')`）都不会切坏
- 第三参数里的 `<<变量>>` 会走后面的变量替换，所以
  `pg_read_file('<<filepath>>')` 这样写是通的
- 第三参数也可以引用**字典槽位的字段**：`<<select(cols,pos,src.col)>>`
  ——表名和列名配套的那种槽位（`src.tbl` / `src.col`）这么用才写得出来

### `<<rep(n,item)>>` —— 重复次数本身是选项

```yaml
slots:
  depth: {options: ["1", "2", "3", "4", "5"], default: "3"}
  form:
    options:
      - {id: nested, name: "....// （删一次后还原）", seq: "....//"}
body: "<<rep(depth,form.seq)>><<filepath>>"
```

`depth=2` → `....//....//`。给它的理由是**有些载荷的长度本身就是参数**：
穿越序列要几层取决于目标路径深度，事先不知道。以前只能把三份 `<<form.seq>>`
硬写在 body 里，用户改不了层数——那正是「写死的取值」里最该消灭的一种。

- `n` 与 `item` 都先按名字查，查不到就当字面量。`n` 求值后必须是数字，否则原样透传
- 超过 **100** 次会报出来并原样透传，不会真的去展开——手滑多打几个 0 是常事，
  而这行代码跑在用户机器上
- 展开结果里的 `<<变量>>` 会走后面的变量替换，所以 item 可以带占位符

### `<<phpser(spec)>>` —— 「按目标定制」那类载荷的出口

有些载荷**没法预先枚举**：PHP 的 POP 链长什么样，取决于目标代码里有哪些类、
属性是什么可见性、嵌套几层。这种时候能固定的只有**格式**，内容是使用者现填的。

而 PHP 序列化的格式里，**每一段都有字节长度前缀**，容器还要声明元素个数——
这两样手写时是静默错：长度差一个字节，`unserialize()` 直接 `Error at offset N`；
`O:3:"Foo":2:{...}` 里声明两个属性却只写一个，也一样。
私有属性还要写成 `\0类名\0属性`，长度得把两个 NUL 一起算进去，肉眼几乎数不对。

所以分工是——**结构你写，长度工具算**：

```yaml
body: "<<phpser(spec)>>"
vars: [spec]
```

```
O:Foo{ bar=s:"x" }                  → O:3:"Foo":1:{s:3:"bar";s:1:"x";}
O:User{ #name=s:"admin" }           → O:4:"User":1:{s:10:"\0User\0name";s:5:"admin";}
a{ i:0=s:"a" i:1=s:"b" }            → a:2:{i:0;s:1:"a";i:1;s:1:"b";}
O:App\Cache{socket=O:SoapClient{uri=s:"http://x"}}
                                    → O:9:"App\Cache":1:{s:6:"socket";O:10:"SoapClient":1:{s:3:"uri";s:8:"http://x";}}
```

| 写法 | 含义 |
| --- | --- |
| `N` / `b:1` / `i:1` / `d:1.5` | 空 / 布尔 / 整数 / 浮点 |
| `s:"文本"` | 字符串，长度按 **UTF-8 字节数** |
| `a{...}` / `O:类名{...}` | 数组 / 对象 |
| 键 `i:0` / `s:"k"` | 数组的整数键 / 字符串键 |
| 键 `name` / `-name` / `#name` | 对象的 public / protected / private 属性 |
| 键 `#类名/属性` | private，但 mangling 用**指定的那个类**（父类的私有属性） |

几条约定：

- `<<phpser>>` 的参数**只能是名字**（不像 `<<select>>` 的第三个参数能写字面量）：
  结构描述动辄上百字符，写进 body 里没人维护得动，校验器也没法替它检查
- 结构描述里**可以嵌 `<<变量>>`**，会先替换再算长度——
  所以 `s:"http://<<lhost>>/"` 这种写法长度是对的
- 没填（名字查不到）→ 原样透传；结构有问题 → **报出来并透传**，
  绝不吐一个半截的串出去
- **父类的私有属性**要用声明它的那个类做 mangling，而外层 `O:` 写的是子类。
  这时用 `#类名/属性名` 显式指定：`O:Sub{ #Base/p=i:1 }` → ` Base p`。
  分隔符取 `/`——PHP 标识符里不出现它，命名空间用的是反斜杠，不会撞
- **引用写 `&标签` + `r:标签` / `R:标签`**。`r:` 是同一个对象，`R:` 是真引用（`&`）：

  ```
  &r O:A{ p=r:r }                      自引用（$a->p = $a）
  O:B{ x=&o O:A{} y=r:o }              两个属性指向同一个对象
  a{ i:0=&z O:Z{} i:1=r:z i:2=r:z }    数组里重复引用同一个对象
  ```

  `&标签` 标在紧跟的那个值前面，**根上也能打**——不打的话最外层对象没名字可指，
  自引用链就写不出来。

  编号由工具算，规则是从真 PHP 实测出来的（先序；键不占号；
  **`r:`/`R:` 的产出本身也占一个号**）。最后一条最容易漏，它决定了引用
  **之后**的所有值会不会偏号。`golden/phpser.yaml` 里有一条样本专门钉它。

- 不做 `E:`（enum，PHP 8.1）和 `C:`（Serializable）——展开规则没实测过，
  宁可不做也不猜。这两类请用 phpggc 生成后当普通变量贴进来。

### 序列化串有真 parser 了

`content_type: [serialized]` 的载荷，运行期会走 `forge/syntax.py` 里的
**PHP 序列化校验器**，检查长度前缀、元素个数、结尾是否恰好。状态是
`ok` / `fail` / `unchecked`（遇到没建模的 `C:`/`R:`/`r:` 报「未校验」而不是
「失败」——判错会让用户去改一条本来正确的载荷）。

它和 `forge/phpser.py` 是**两份独立实现**，刻意不共用代码：
共用的话，同一个理解错误会在生成和校验里同时成立，校验就成了自我确认。

两条边界，都按「宁可说没能力判，也别判错」处理：

- **先看首个类型标记**。`content_type: serialized` 底下不止 PHP——pickle 协议 0
  也是纯 ASCII。第一版没这道闸，一条完全正确的 pickle 载荷被判成
  「PHP 序列化校验未通过：认不出的类型标记 'c'」。判错比不判更糟，
  用户会去改一条本来是对的载荷
- **`S:`（转义字符串）的长度前缀不校验**。它是 unserialize 认、serialize 不产的形态，
  内容带转义，声明长度和原始字节数本来就对不上。只扫结构，并在通过时**如实说明**
  「有 N 处 S: 的长度没有校验」——不做过头承诺

所以加 PHP 序列化模板时**顺手断言 `syntax: ok`**——它是免费的回归防线。
`run_golden.py` 的 `smoke_phpser` 还会遍历所有 serialized 模板的**每个槽位取值**，
把过不了校验的挑出来（`deser.php.syntax.object` 曾经有个 `n` 槽位能选 2/3，
但 body 里只写得下一个属性对，产出 `O:3:"Foo":2:{...}`——默认值恰好是 1，
黄金样本从没碰到，是这条检查把它抓出来的）。

### 槽位选项的值里可以嵌变量

```yaml
slots:
  expr: {options: ["group_concat(<<col>>)", "group_concat(<<col>>,0x7c)"], default: "group_concat(<<col>>,0x7c)"}
vars: [col]
body: "<<close>> UNION SELECT <<select(cols,pos,expr)>> FROM <<table>> <<comment>>"
```

槽位先填、变量后替换，所以嵌在选项里的 `<<col>>` 到下一阶段才求值，能通。

**但只能引用变量，不能引用别的槽位。** `fill_slots` 是按声明顺序逐个 `replace` 的，
槽位引用槽位的结果取决于谁先声明——这种不确定性不该出现在数据里，校验器会直接报错。

### 引号属于模板，不属于槽位

`INTO OUTFILE '<<filepath>>'` 这种写法里，引号在 body 里、包住占位符。

写成 `<<select(cols,pos,code)>>` 再让槽位取值带引号是**下策**：槽位描述的是
「内容是什么」，SQL 的字面量语法是模板的事。真要那么写也行，但漏了引号就会产出
`SELECT <?php ...?>,2,3` —— 语法合法、语义已错的典型。加模板时用黄金样本把这条钉住。

**注意**：第三个参数如果本该是变量名却拼错了，会**静默变成字面量**（产出 `1,exrp,3`）。
校验器查不了这个——它无法区分「拼错的变量名」和「SQL 里的裸标识符」（`banner`、`user`）。
写的时候留意产出。

**槽位 vs 变量**：槽位是枚举（下拉选，选项写在数据里，可穷举校验）；变量是自由文本。

**字典槽位**用于「一组值必须配套」的场景，典型是模板定界符：

```yaml
slots:
  d:
    options:
      - {id: jinja2, open: "{{", close: "}}"}
      - {id: erb,    open: "<%=", close: "%>"}
body: "<<d.open>>7*7<<d.close>>"
```

拆成两个独立槽位是不行的——用户能拼出 `{{` + `%>` 且两边取值各自都合法，校验器拦不住。

**`<<len(NAME)>>` 是字节数，不是字符数**。`管理员` 是 3 个字符但 9 个字节，
PHP 序列化写 `s:3:` 会直接解析失败。和 HTTP 的 `Content-Length` 是同一个坑。

## 5. `requires` 必须来自受控词表

词表在 `data/requires.yaml`，42 个键。`validate_rules.py` 强制。

词表本身写在 `data/requires.yaml`（带 `name` 和 `desc`）。
**界面上"字段 8 目标前提"就是它**，每个键会标出勾上会筛掉多少条模板。
**没有单独的"列词表"命令**了——界面上直接看得到。

**写全它。** 这是最容易犯错的地方，而且错了不容易发现——`requires` 只是展示文本时，
漏写几条没人注意；一旦它变成筛选器，漏写就意味着**用户声明「出不了网」后仍会看到需要出网的模板**。

实测过：从自由文本收敛成词表后，一次性查出 **12 条模板漏声明前提**
（三条反弹 shell 没声明「需要监听」、DNS 带外没声明「需要出网」……）。

**写新模板时自问**：这条载荷要生效，目标必须具备什么？把它逐个对上词表里的键。

### `requires` 是**合取**，表达不了「或」

`requires: [a, b]` 的意思是「a 和 b 都得有」。所以**「满足其一即可」写不出来**：

> JWT 的 `claims.privilege`（把 `admin` 改成 `true`）要求目标至少在
> `alg=none` / 弱密钥 / 算法混淆 / kid 注入里中了一条——这是**或**关系。
> 硬写其中一条会让另外三条路径下的用户看不到它，所以只能 `requires: []`
> 加上在 `desc` 里说清「必须配一条能过验签的头」。

这类模板的前提是「你手上已经有一条能验过的 token」，属于**流程前提**而非目标属性，
本词表管不了。诚实的做法是留空 + 写进 `desc`，而不是随便挑一条凑数——
凑数会让前提筛选给出错误的收窄结果。

### 提示名是全局的，撞名就改名

`data/labels.yaml` 里的 `slot` / `var` 两张表按名字全局查，不区分漏洞类型。
同一个名字在两个类型里含义不同时，只能有一个中文，所以**改名比改表便宜**：

> JWT 里的 `sub`（token 主体）撞上了 SSRF 的 `sub`（子域名），
> JWT 模板只能改用 `subject`；`n`（RSA 模数）同理改成了 `modulus`。

写新模板时如果发现常用的名字已经被占了、而中文文案对不上，**换个名字**。

## 6. 黄金样本的纪律 ⭐

### 期望值必须独立来源

**不要跑一遍工具把输出粘进 `expect`。** 那样测试只是把当前行为（含 bug）固化成规范，
永远不会失败，也永远发现不了「替换时机搞反」「编码层顺序错」这类静默错误。

**怎么手算**：读你写的 `body`，按方案 §10 的编码 / 转义管线逐层推——
槽位填充 → 变量替换 → 按序应用绕过 → 传输编码 → 输出渲染。

### 两种失败要分清

```yaml
# 生成跑完了，但没有可用模板
expect:
  ok: false

# 用户输入本身非法，抛 RuleError
expect:
  raises: "不在 options 里"
```

### 可以断言的不止 payload

```yaml
expect:
  payload: "..."           # 逐字节比对
  outputs: {curl: "..."}   # 指定输出层
  syntax: ok               # ok / fail / unchecked
  checks_count: 1          # 成品约束校验的提示条数
  note: 版本不符            # 软标记
```

### 测试的三种强度

| 命令 | 抓什么 |
| --- | --- |
| `python validate_rules.py` | **永久性**错误：字段、id 前缀、占位符、互斥对称、词表封闭性 |
| `python run_golden.py` | **静默**错误：替换时机、编码层顺序。附带覆盖率检查 |
| `python run_golden.py --mutate` | **假覆盖**：样本写了这个 id 但没在断言它 |

`--mutate` 逐条篡改模板 body，看是否**至少有一条样本会失败**。它在本项目抓到过两次真问题——
一次是参数默认值（样本全绿但功能是坏的），一次是 `skip_quoted` 的空样本
（加不加开关结果一样）。**加完模板跑一次 `--mutate`。**

## 7. 踩过的坑（照着躲）

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| `license: -` | YAML 里 `-` 是序列语法不是 null，**文件直接解析失败** | 写 `license: ""` |
| 双引号标量里写 `\$` | `\$` 不是合法转义，**整个文件解析失败**（Log4j 载荷最容易踩，因为值里全是 `${}`） | 双引号里 `$` 不用转义，直接写 `${lower:j}` |
| 槽位取值自带分隔符，body 又补一个 | `drive: C:` + body `<<drive>>:/...` = `C::/`，语法合法、路径已错 | 分隔符只在一处出现。手推一遍期望值就能看出来 |
| 把回显位/层级这类「因目标而异」的取值写死在 body 里 | 用户只能手改数据文件 | 做成槽位，或交给 `<<select(cols,pos,...)>>` |
| `case` / `replace` 绕过没开 `skip_quoted` | 改到字符串字面量**里面**：`'a b'` → `'a+b'`。语法依旧合法，语义已经错了 | 加 `skip_quoted: true` |
| `requires` 漏声明 | 前提筛选形同虚设 | 见 §5 |
| 互斥单向声明 | 提示取决于选中顺序 | `incompatible_with` 必须双向，校验器会查 |
| 块标量 `\|` 而非 `\|-` | 末尾多一个换行，黄金样本逐字节比对时挂 | 载荷用 `\|-` |
| `desc` / `name` 里含 ` #` 且**不加引号** | 行内 ` #` 是 YAML 注释起点，值被**静默截断**：`Pug 的 #{} 插值…` 只剩 `Pug 的`。文件看着正常、校验也过 | 加引号。`validate_rules.py` 会扫出来 |
| 值以 `@` `*` `&` `!` `%` 开头且不加引号 | YAML 保留指示符，**文件直接解析失败**（这个会报错，不算静默） | 加引号 |
| 行尾注释 + 按行替换 | 替换会切坏 YAML | 注释独占一行 |
| 要输出**字面量 `<` 紧跟占位符** | 写 `<<name>>` 会把 `<` 吃掉 | 写 **三个**尖括号 `<<<name>>`：前两个是字面量，后两个是占位符边界。**看着像手滑，但它是对的** |
| 想写二进制载荷 | 表达不了 | 见方案 §2「不做什么」与 §7 内容类型枚举；二进制走外部生成器 + 外层包装模板 |

---

## 8. 一条好模板的标准

机械合规只是及格线，下面这些校验器查不了：

- [ ] **载荷真实可用**——不是从语法推出来的，是你见过/用过/核对过出处的
- [ ] **`requires` 完整**——列出所有必要前提，包括"显然"的那些（能出网、有监听）
- [ ] **`desc` 说清了判断依据**——什么时候用它、什么时候它不 work
- [ ] **`status` 诚实**——没实际验证过就写 `theory`，别写 `golden`
- [ ] **有黄金样本**，且期望值是手算的
- [ ] **版本区间正确**——该有的版本限制写在 `version` 里，而不是含糊地不提
- [ ] 跑过 `validate_rules.py` + `run_golden.py` + `--mutate`，全绿
