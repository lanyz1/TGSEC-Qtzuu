# 测试流程

> **测试时不要连生产/未授权目标。** 这个工具只生成文本，但你接下来拿它做的事由你负责。

分四段，从自动化到手工，从"能不能跑"到"产出对不对"。**建议按顺序做**——
前一段不过就别往下走。

| 段 | 耗时 | 做什么 | 覆盖什么 |
| --- | --- | --- | --- |
| [一、自检](#一自检5-分钟) | 5 分钟 | 三条命令 | 规则库、生成结果、全部冒烟 |
| [二、启动器验收](#二启动器验收5-分钟) | 5 分钟 | 双击 / 命令行 | 我在沙箱里验不到的那部分 |
| [三、手工走查](#三手工走查20-分钟) | 20 分钟 | 按场景点一遍 | 交互手感、中文渲染、布局 |
| [四、产出正确性](#四产出正确性最重要) | 视情况 | **拿真实环境核对** | 工具明确不保证的那部分 |

## 一、自检（5 分钟）

三条命令，全绿就过。

```bash
cd D:\xgj

python validate_rules.py      # 规则库静态检查
python run_golden.py          # 黄金样本 + 六组冒烟 + 文档一致性
python run_golden.py --mutate # 逐条篡改模板，验证样本真的在断言
```

**期望输出**（数字对不上不一定是坏的，但要知道为什么变）：

```
模板 584 条，绕过 41 条，覆盖 35 个 (漏洞类型, 内容类型) 组合
错误 0，警告 0

黄金样本 1053 条，失败 0 条，覆盖警告 0 条

黄金样本 1053 条，失败 0 条，覆盖警告 0 条
```

### 检查点

- [ ] 三条命令**退出码都是 0**（`echo $?` 或看 `echo %errorlevel%`）
- [ ] `validate_rules.py` 的「错误」和「警告」**都是 0**
- [ ] `run_golden.py` 的「失败」和「覆盖警告」**都是 0**
- [ ] `--mutate` 跑完后失败仍是 0（它约需 5 秒，比前两条慢）

### 这四条各抓什么

| 命令 | 抓的错 | 举例 |
| --- | --- | --- |
| `validate_rules.py` | **永久性**错误：写错的模板会一直错下去 | id 前缀不符、占位符没声明、YAML 里 ` #` 把描述截断 |
| `run_golden.py` | **静默**错误：产出看着对其实错了 | 替换时机搞反、编码层顺序错 |
| 同上（冒烟） | 界面与引擎不一致 | 界面显示"不限"、实际按 sqli 过滤 |
| `--mutate` | **假覆盖**：样本写了 id 但没断言它 | 加不加某个开关结果都一样 |

### 红了怎么办

先看是哪一类：

| 现象 | 大概率原因 |
| --- | --- |
| `模板 N 条` 变了 | 加了/删了模板。**去改 `使用说明.md` 里的数字**——`smoke_doc` 会盯着它 |
| `没有黄金样本` 警告 | 加了模板没配样本。跑 `python new_template.py` 补 |
| `FAILED` 某条黄金样本 | 改了模板 body 但没改期望值；或者真改坏了 |
| `假覆盖` 警告 | 样本没真正断言那个模板——补一条断言它的样本 |
| `引用了已删除的子命令` | 文档里还在教用户敲不存在的命令 |

## 三、手工走查（20 分钟）

两条路径都要走：**TUI**（`forge.bat`）和 **GUI**（`forge-gui.vbs`）。
GUI 的每一项在 TUI 里都有对应，反之亦然——**两边对不上就是 bug**。

### 场景 1：SQL 注入（5 分钟）

按这个顺序点，每步看一眼：

- [ ] **字段 1** 改漏洞类型 → 列表变了，字段 1 显示的是**新值**
- [ ] **字段 2** 选 `mysql` → 列表收窄到 36 条
- [ ] **字段 8** 勾「页面有回显位」+「目标可出网」
  - 列表降到 **24 条**
  - TUI 底部出现 `（多出 N 条：…）`
  - **GUI**：勾选框上带 `(N)` 计数
- [ ] **`t` 选模板** → 选 `sqli.mysql.union.basic`
- [ ] **`s` 填参数** → 四个槽位（闭合符 close / 列数 cols / 回显位 pos / 注释符 comment）
  - **参数区显示的是默认值**（`闭合符 close = "'"`），**不是空串**
- [ ] **字段 5** 输出层填 `raw,curl` → 生成后两个都有
- [ ] **`g` 生成**：

```
组装链：
  槽位填充         ' UNION SELECT 1,2,3 -- -
  变量替换         ' UNION SELECT 1,2,3 -- -

--- raw ---
' UNION SELECT 1,2,3 -- -

--- curl ---
curl 'http://example.com/?id=%27%20UNION%20SELECT%201%2C2%2C3%20--%20-'
```

- [ ] curl 那行**复制出来**，粘到记事本——**引号完整，没有被截断**

**这里最容易出错的**：`%27` 是 `'` 的 URL 编码，`%20` 是空格。
如果你看到的是原文没编码，说明输出层选错了。

### 场景 2：叠绕过，看组装链（3 分钟）

- [ ] **字段 7** 加 `bypass.case.alternate`，再加 `bypass.url`
- [ ] 生成 → 组装链应该**逐层显示**，各步骤名左对齐：

```
组装链：
  槽位填充     ' UNION SELECT 1,2,3 -- -
  变量替换     ' UNION SELECT 1,2,3 -- -
  交替大小写   ' UnIoN SeLeCt 1,2,3 -- -
  URL 编码     %27%20UnIoN%20SeLeCt%201%2C2%2C3%20--%20-
```

- [ ] **换成「注释替代空格」+「URL 编码」**，两种顺序各生成一次：

| 顺序 | 产出 |
| --- | --- |
| 先空格后编码 | `%27%2F%2A%2A%2FUNION%2F%2A%2A%2FSELECT…` |
| 先编码后空格 | `%27%20UNION%20SELECT…` |

第二种顺序里，`注释替代空格` **什么都没做**——因为空格已经变成 `%20` 了。
工具应该主动提示：

```
提示：绕过 注释替代空格 没有改变载荷 —— 可能被前一步抵消了（检查绕过顺序）
```

> 绕过是"盲盒"还是"可见的"，差别就在这条组装链上。
>
> 注意：**不是所有顺序都有影响**。比如「交替大小写」和「URL 编码」互换顺序产出完全相同
> （字母编码后还是字母，大小写替换照样能找到目标）。所以别拿这组做对照实验。

### 场景 3：线索提示（3 分钟）

- [ ] 叠加两个互斥的绕过（比如 `bypass.space.plus` 和 `bypass.space.comment`）
  - TUI：绕过菜单里出现 `⚠ 互斥：…`
  - GUI：绕过区出现红字
- [ ] 生成 → 应该出**提示**（不是拦截），产出照常

### 场景 4：多行载荷与长载荷（3 分钟）

这两类在终端里最容易显示得一塌糊涂。

- [ ] 漏洞类型选 `xxe`，模板 `xxe.generic.file.read`，变量 `filepath=/etc/passwd`
  - 载荷是**三行 XML**，TUI 里应该**分行显示**，不是挤成一行
  - 末尾应显示 `语法：xml 语法校验通过`（XML 有真 parser）
- [ ] 漏洞类型选 `upload`，提交方式选 `multipart`，输出层加 `request`
  - 请求体有好几行，应该**完整显示**，不截断

### 场景 5：空结果与放宽（3 分钟）

- [ ] 漏洞类型选 `rce`，**内容类型选 `sql-expression`**（故意错配）→ 应该空
  - 期望：`当前条件下没有可用模板。放宽下列任一条：` + 两条建议

- [ ] **GUI 特有**：勾上「显示缺前提的」
  - 灰显的模板列出来，带原因
  - 选一条灰显的 → 出现「放宽这 N 项并用它」按钮 → 点它 → 那条变可用并被选中

### 场景 6：错误输入（2 分钟）

- [ ] TUI 里输 `zzz` → 应提示「认不出的命令」，**不崩**
- [ ] 在菜单里输 `99` → 应提示范围，**不崩**
- [ ] 任何界面里按 `Ctrl-C` → 应正常退出，不留脏状态

### 场景 7：两个界面对得上吗（1 分钟）

- [ ] 同样的选择在 TUI 和 GUI 里各生成一次 → **产出应该逐字节相同**

> 两边共用同一个引擎，所以这条必须成立。不一样就说明有界面绕过了引擎。

## 四、产出正确性（最重要）

**工具明确不保证这一项**——它只管拼字符串，不管拼出来的东西在目标上能不能用。
所以这一段只能你自己打靶验。

### 挑几条去真环境核对

建议至少覆盖这四类形态：

| 类型 | 挑一条 | 验什么 |
| --- | --- | --- |
| SQL 表达式 | `sqli.mysql.union.basic` | 闭合符对不对、列数猜得对不对、注释符在目标方言里成不成立 |
| 系统命令 | `rce.linux.reverse.bash` | 反弹回得来吗、`/dev/tcp` 在目标 shell 里有没有 |
| XML 文档 | `xxe.generic.file.read` | 解析器有没有禁用外部实体、回显位在哪 |
| 序列化文本 | `deser.php.syntax.string` | **长度前缀对不对**（中文尤其容易错） |

### 尤其要盯的三类静默错误

工具会把这三类**当成提示报出来**，但不会拦你：

- [ ] **`Content-Length` / PHP `s:N:` 的长度**
      自己数一遍：是**字节数**不是字符数。`管理员` 是 3 字符 / 9 字节
- [ ] **引号配对**
      载荷里的 `'` 和 `"` 有没有提前闭合。工具只在"变量落在引号字面量内"时提示
- [ ] **双重编码**
      绕过层编了一次、传输层又编一次。工具会提示"共 N 次"——**本意是 WAF 绕过就忽略**

### 记下来

打靶时如果发现某条模板产出不对，**别直接改工具**，先分清：

| 情况 | 怎么办 |
| --- | --- |
| 模板 body 写错了 | 改 `data/` 里的模板，跑 `validate_rules.py` + `run_golden.py` |
| 模板能出，但缺个前提没声明 | 补 `requires`（见 `模板写作规范.md` §5） |
| 工具拼错了（编码/替换顺序） | **这是工具 bug**，把状态和期望产出给我 |
| 载荷语法对，但目标上不成立 | 正常——工具不管这个，是你选错了模板或前提 |
