# 公开来源索引

本文件保留 16 个直接支撑协议事实、授权评估方法和实现案例的公开来源入口。

## 取证优先级

1. 当前 RFC 及其更新文档：协议规范事实。
2. 厂商当前公告与补丁：受影响条件、版本和实现根因。
3. CWE、OWASP：分类与授权评估方法。
4. 公开研究：攻击面假设和历史案例，不作为通用规范。

版本命中、研究示例、错误码或延迟都不能单独证明具体部署可利用。

## 规范

- `S01` [RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html)：HTTP 语义、字段与消息内容的共同基础。
- `S02` [RFC 9112: HTTP/1.1](https://www.rfc-editor.org/rfc/rfc9112.html)：H1 消息定界、`Transfer-Encoding` / `Content-Length` 冲突、不可恢复错误与连接关闭。
- `S03` [RFC 9113: HTTP/2](https://www.rfc-editor.org/rfc/rfc9113.html)：畸形消息、连接专属字段、字面 `TE: trailers` 和 `PROTOCOL_ERROR`。
- `S04` [RFC 9114: HTTP/3](https://www.rfc-editor.org/rfc/rfc9114.html)：H3 畸形消息、连接字段限制与 `H3_MESSAGE_ERROR`。
- `S05` [RFC 9931](https://www.rfc-editor.org/rfc/rfc9931.html)：特定 HTTP/1.1 CONNECT 乐观协议切换规则；不得泛化到所有 Upgrade。

## 分类与授权评估指南

- `S06` [CWE-444](https://cwe.mitre.org/data/definitions/444.html)：多组件不一致解释 HTTP 消息的根因分类。
- `S07` [OWASP WSTG v4.2](https://owasp.org/www-project-web-security-testing-guide/v42/4-Web_Application_Security_Testing/07-Input_Validation_Testing/15-Testing_for_HTTP_Splitting_Smuggling)：稳定版授权评估目标和灰盒前提；旧 RFC 表述需用当前规范校正。
- `S08` [OWASP WSTG Latest WSTG-INPV-16](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Input_Validation_Testing/16-Testing_for_HTTP_Request_Smuggling)：现代攻击面线索；页面可变且操作性示例不复制入本地数据。
- `S16` [CWE-113](https://cwe.mitre.org/data/definitions/113.html)：用于区分 CR/LF 拆分与 CWE-444 的组件解释分歧。

## 公开研究

- `S09` [Watchfire 2005 白皮书](https://www.cgisecurity.com/lib/HTTP-Request-Smuggling.pdf)：术语与早期多组件威胁模型；只保留书目链接和原创摘要。
- `S10` [HTTP Desync Attacks: Request Smuggling Reborn](https://portswigger.net/research/http-desync-attacks-request-smuggling-reborn)：现代代理链、连接复用与证据模型。
- `S11` [HTTP/2: The Sequel is Always Worse](https://portswigger.net/research/http2)：H2 到 H1 降级与请求重建边界；降级本身不是漏洞。
- `S12` [Browser-Powered Desync Attacks](https://portswigger.net/research/browser-powered-desync-attacks)：客户端侧 Desync、提前响应和请求体生命周期线索。
- `S13` [HTTP/1.1 Must Die: The Desync Endgame](https://portswigger.net/research/http1-must-die)：减少上游 H1 接缝的研究主张，不是 IETF 退役公告。

## 厂商一手案例

- `S14` [Apache HTTP Server 2.4 Vulnerabilities](https://httpd.apache.org/security/vulnerabilities_24.html)：
  - CVE-2023-25690 需同时核验 `mod_proxy`、特定宽泛重写/代理匹配、用户可控值回插、版本或补丁状态与拓扑。
  - CVE-2022-22720 的核心是请求体丢弃错误后连接生命周期处理；版本命中不等于部署可利用。
- `S15` [HAProxy CVE-2021-40346 公告](https://www.haproxy.com/blog/september-2021-duplicate-content-length-header-fixed)：内部 HTTP 表示中的字段名长度检查缺失可绕过重复长度检查；仍须核验具体构建、补丁回移和产品形态。
